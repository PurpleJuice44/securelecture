암호학 Level 3 장(chapter)

RSA 기초

공개키/개인키 구조와 소인수분해 기반을 이해한다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • 공개키로 암호화, 개인키로 복호화
  • 안전성 기반: 큰 수 소인수분해 어려움
  • 전자서명에도 사용

2. 핵심 개념

  • 공개키로 암호화, 개인키로 복호화
  • 안전성 기반: 큰 수 소인수분해 어려움
  • 전자서명에도 사용

2-2. 동작 원리 심화: 열쇠 두 개의 수학

RSA는 곱하기는 쉽고 소인수분해는 어려운 비대칭에 기대어 섭니다. 두 소수 p·q를 곱해 n을 만들고, 공개키(e, n)는 나누고 개인키(d)는 숨깁니다. 암호화는 공개키로, 복호화는 개인키로만 됩니다.

flowchart TD P["소수 p·q 선택"] --> N["n = p×q 계산"] N --> E["공개키 e 선택"] E --> D["개인키 d 계산"] E --> PUB["공개키 배포
암호화·서명검증"] D --> PRI["개인키 보관
복호화·서명"] PUB --> C["암호문"] C --> PRI

읽는 법: 왼쪽이 키 생성, 오른쪽이 사용입니다. n을 소인수분해하면 d가 새므로, 소수가 클수록 안전합니다.

2-3. 용도표

용도쓰는 키푸는 키
기밀성(암호화)수신자 공개키수신자 개인키
인증(서명)송신자 개인키송신자 공개키
키 교환일회성+공개키 조합TLS 핸드셰이크

3. 예제

작은 소수(p=61,q=53)로 손계산 체험 (개념)

3-2. 심화 예제: 손계산과 openssl

# 손계산 (p=61, q=53)
# n = 61*53 = 3233, phi = 60*52 = 3120
# e=17 선택 → d=2753 (17*2753 mod 3120 = 1)
# 암호화: c = m^e mod n / 복호화: m = c^d mod n
python3 -c "print(pow(65, 17, 3233), pow(2790, 2753, 3233))"
# openssl 실전 키 쌍
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out priv.pem
openssl rsa -pubout -in priv.pem -out pub.pem
openssl pkeyutl -encrypt -pubin -inkey pub.pem -in plain.txt -out enc.bin
openssl pkeyutl -decrypt -inkey priv.pem -in enc.bin -out dec.txt

4. 실습

  1. 키 쌍 생성 과정을 순서대로 적어본다.
  2. p=61·q=53 손계산을 따라 해본다.
  3. openssl로 2048비트 키 쌍을 만든다.
  4. 공개키 암호화→개인키 복호화 왕복을 수행한다.
  5. 개인키 유출 시 파급을 한 줄로 적는다.

5. 퀴즈

  1. 공개키와 개인키의 역할은?
  2. 소인수분해가 어려운 이유는?
  3. 암호화와 서명의 키 사용이 반대인 이유는?
  4. 키 길이가 길수록 좋은 점과 나쁜 점은?
  5. RSA로 긴 파일을 직접 암호화하지 않는 이유는?
정답 보기
  1. 공개키는 나누어 암호화·검증에, 개인키는 보관해 복호화·서명에 쓴다.
  2. 큰 수의 소인수분해에 알려진 빠른 방법이 없기 때문이다.
  3. 암호화는 받는 사람만 풀게, 서명은 보낸 사람이 맞음을 보이기 위해서이다.
  4. 안전해지지만 연산이 느려진다.
  5. 느리고 길이 제한이 있어 대칭키를 감싸는 용도로 쓴다.

5-2. 한눈에 보는 키 흐름

sequenceDiagram participant A as 송신자 participant B as 수신자 B->>A: 공개키 전달 A->>A: 공개키로 암호화 A->>B: 암호문 전송 B->>B: 개인키로 복호화

읽는 법: 공개키는 길에 뿌려도 되고, 개인키는 절대 길에 내놓지 않습니다.

6. 흔한 실수

  • 공개키로 복호화하려 드는 경우. 방향을 반대로 이해한 것이다.
  • 작은 소수·짧은 키를 실전에 쓰는 경우. 2048비트 이상이 기준이다.
