Misc Level 7 장(chapter)

pwntools 입문

풀이 자동화 도구의 기본을 익힌다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • process/remote 연결
  • p64/p32 패킹, sendlineafter
  • 템플릿으로 풀이 속도 향상

2. 핵심 개념

  • process/remote 연결
  • p64/p32 패킹, sendlineafter
  • 템플릿으로 풀이 속도 향상

2-2. 동작 원리 심화: 연결·포장·동기화

pwntools는 연결하고→주소를 포장하고→때를 맞춰 보내는 3박자입니다. process·remote로 붙고, p64로 주소를 싸고, sendlineafter로 프롬프트를 기다렸다 보냅니다.

flowchart TD C["연결
process·remote"] --> P["포장
p64·p32"] P --> S["동기화
sendlineafter"] S --> R["수신·판정
recvuntil"]

읽는 법: 붙이기→싸기→맞추기의 순서입니다. 동기화를 빼먹으면 타이밍이 어긋나 실패합니다.

2-3. 함수표

함수용도
process·remote로컬·원격 연결
p64·u64주소 포장·해제
sendlineafter문구 대기 후 전송
recvuntil구분자까지 수신

3. 예제

r = process('./vuln'); r.sendline(b'A'*72) (개념)

3-2. 심화 예제: 템플릿(실습 대상만)

from pwn import *
# 로컬↔원격 한 줄 전환
# r = process("./vuln")
r = remote("실습호스트", 9000)  # 허가된 실습 대상만!
r.sendlineafter(b"입력:", b"A"*72)
print(r.recvuntil(b"결과").decode(errors="ignore"))
# 포인트: sendlineafter의 대기 문구는 실제 출력과 정확히 일치시킬 것

4. 실습

  1. 연결→전송→수신 스크립트를 작성한다.
  2. p64·u64 왕복 변환을 확인한다.
  3. sendline과 sendlineafter 차이를 실험한다.
  4. 로컬·원격 전환을 연습한다(실습 대상).
  5. 템플릿 파일 1개를 저장한다.

5. 퀴즈

  1. p64의 용도는?
  2. 로컬/원격 전환 방법은?
  3. sendlineafter가 필요한 이유는?
  4. u64 사용 전 필요한 처리는?
  5. 연결 종료를 명시해야 하는 이유는?
정답 보기
  1. 주소를 8바이트 리틀엔디언으로 포장하는 것이다.
  2. process와 remote 한 줄을 교체하는 것이다.
  3. 상대 출력을 기다렸다 보내 타이밍을 맞추기 위해서이다.
  4. 8바이트 패딩(ljust)이다.
  5. 좀비 연결·포트 고갈을 막기 위해서이다.

5-2. 한눈에 보는 입출력 동기화

sequenceDiagram participant S as 스크립트 participant T as 대상 S->>T: 연결 T-->>S: 프롬프트 출력 S->>T: sendlineafter 전송 T-->>S: 결과 반환

읽는 법: 기다렸다 보내는 것이 핵심입니다. sleep 대신 출력 문구 대기를 씁니다.

6. 흔한 실수

  • 대기 문구 오타로 영원히 기다리는 경우
  • 인코딩을 안 맞춰 바이트·문자열이 섞이는 경우
