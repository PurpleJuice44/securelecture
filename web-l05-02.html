웹 Level 5 장(chapter)

SSRF (서버측 요청위조)

서버를 대신 공격자로 쓰는 취약점과 대응을 배운다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • 내부망·클라우드 메타데이터(169.254.169.254) 접근
  • URL 스킴·호스트 allowlist로 제한
  • 외부 요청 응답/리다이렉트 차단

2. 핵심 개념

  • 내부망·클라우드 메타데이터(169.254.169.254) 접근
  • URL 스킴·호스트 allowlist로 제한
  • 외부 요청 응답/리다이렉트 차단

2-2. 동작 원리 심화: 서버가 공격자의 발이 되는 구조

썸네일 생성·웹훅·파일 가져오기처럼 서버가 대신 URL에 접속하는 기능이 SSRF의 무대입니다. 공격자가 URL을 내부 주소로 바꾸면, 방화벽 안쪽에 있는 서버가 내부망을 대신 찌릅니다.

url 파라미터 조작"] --> S["서버
URL 접속 기능"] S --> E{"어디에 접속하는가"} E -->|외부 허용| O["외부 사이트

관리자 페이지"] E -->|메타데이터| M["169.254.169.254

읽는 법: 서버의 시선에서는 전부 정상 요청입니다. 그래서 접속 전에 허용 목록으로 목적지를 제한해야 합니다.

2-3. 우회 vs 대응표

우회 시도원리대응
도메인→내부 IP 해석DNS rebinding·공격자 DNS해석 후 IP 대역 검사
리다이렉트 경유허용 도메인→내부로 점프리다이렉트 금지·최종 URL 검사
10진·16진·단축 IP표기 변형정규화 후 사설대역 차단
@·# 트릭파서 혼동표준 URL 파서+allowlist

3. 예제

?url=http://169.254.169.254/latest/meta-data/  (실습 환경에서만)

3-2. 심화 예제: 허용·차단 매트릭스(실습 앱)

# 외부·내부·메타데이터·리다이렉트 동작 비교
for u in "http://example.com/" "http://127.0.0.1:8080/admin" \
         "http://169.254.169.254/latest/meta-data/" "http://0x7f.0.0.1/" \
         "http://허용도메인/redirect?to=http://127.0.0.1/"; do
  echo -n "$u : "
  curl -s -o /dev/null -w "%{http_code}\n" "http://실습호스트/fetch?url=$u"
done

4. 실습

  1. 실습 앱의 URL 파라미터에 내부/외부 주소를 넣어 동작을 비교한다.
  2. 메타데이터 주소 요청 시 응답을 확인하고 위험을 기록한다.
  3. 리다이렉트 경유 우회가 막히는지 시험한다.
  4. allowlist 적용 후 매트릭스를 다시 그린다.
  5. 차단 로그가 남는지 확인한다.

5. 퀴즈

  1. 메타데이터 접근이 위험한 이유는?
  2. 대응책 2가지는?
  3. 도메인 allowlist만으로 부족한 이유는?
  4. 리다이렉트를 따라가면 안 되는 이유는?
  5. 클라우드 키가 탈취되면 이어지는 피해는?
정답 보기
  1. 인스턴스 임시 자격증명 등 클라우드 제어 키가 있어 인프라 전체가 넘어가기 때문이다.
  2. 스킴·호스트 allowlist와 사설대역 차단, 리다이렉트 금지이다.
  3. 공격자 DNS가 허용 도메인을 내부 IP로 해석(DNS rebinding)할 수 있기 때문이다.
  4. 허용 도메인이 내부 주소로 점프시켜 검사를 우회하기 때문이다.
  5. 스토리지·DB 등 연결된 자원 전체에 접근해 데이터 유출·리소스 악용으로 번진다.

5-2. 한눈에 보는 검증 순서

sequenceDiagram participant A as 공격자 participant S as 서버 participant N as 네트워크 A->>S: url 파라미터 전달 S->>S: 스킴·호스트 allowlist S->>S: DNS 해석 후 IP 대역 검사 S->>S: 리다이렉트 금지 확인 S->>N: 허용된 경우만 접속

읽는 법: 문자열 검사가 아니라 해석된 최종 IP를 기준으로 판단합니다. 검사는 접속 직전에 합니다.

6. 흔한 실수

  • 문자열에 127.0.0.1만 막고 10진·16진 표기를 놓치는 경우
  • 첫 URL만 검사하고 리다이렉트 목적지는 검사하지 않는 경우
