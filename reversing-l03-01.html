리버싱 Level 3 장(chapter)

동적 분석 (gdb)

브레이크포인트로 실행 흐름을 추적한다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • break *main, run, ni(다음)/si(들어가기)
  • info registers로 레지스터 확인
  • x/s $eax 로 메모리 문자열 확인

2. 핵심 개념

  • break *main, run, ni(다음)/si(들어가기)
  • info registers로 레지스터 확인
  • x/s $eax 로 메모리 문자열 확인

2-2. 동작 원리 심화: 멈추고 엿보기

디버거는 CPU와 메모리 사이에 끼어들어 멈추고→들여다보고→한 칸씩 나아갑니다. 브레이크포인트가 멈춤쇠, ni·si가 한 칸 이동, info registers·x/s가 엿보기입니다.

flowchart TD B["break *main
멈춤쇠 설치"] --> R["run
실행"] R --> S["정지 지점 도달"] S --> I["info registers
레지스터 스냅샷"] I --> X["x/s 주소
메모리 문자열"] X --> N{"ni vs si"} N -->|ni| O["다음 줄
함수 통과"] N -->|si| F["함수 안으로
내부 추적"]

읽는 법: 멈춤→관찰→이동의 반복입니다. si는 깊이 들어가고 ni는 건너뜁니다. 관심 없는 라이브러리 함수는 ni로 통과합니다.

2-3. gdb 치트시트

명령효과언제
b *mainmain 시작에 정지분석 시작점
r [인자]실행매 세션 시작
ni / si한 명령 진행분기 추적
info registers레지스터 전부비교 전후
x/s $eax문자열 보기입력·정답 확인
c다음 정지점까지루프 탈출

3. 예제

gdb ./a.out
(gdb) b *main
(gdb) r
(gdb) ni

3-2. 심화 예제: 비교 분기 추적 세션

gdb -q ./crackme
(gdb) b *main
(gdb) r AAAABBBB
(gdb) disas              # 비교·분기 위치 파악
(gdb) b *0x401234        # strcmp 호출 직후에 정지
(gdb) c
(gdb) info registers eax # 반환값 확인 (0=일치)
(gdb) x/s $esi           # 비교된 입력 문자열
(gdb) si                 # 분기 안으로 한 칸

4. 실습

  1. main에 걸고 레지스터 값을 기록해본다.
  2. 입력값을 바꿔가며 비교 결과를 관찰한다.
  3. ni와 si의 차이를 함수 호출에서 체험한다.
  4. x/s로 스택·레지스터가 가리키는 문자열을 읽는다.
  5. 분기 명령 주소와 점프 여부를 표로 정리한다.

5. 퀴즈

  1. ni와 si의 차이는?
  2. 브레이크포인트의 용도는?
  3. strcmp 반환값 0의 의미는?
  4. 분기 추적 시 레지스터보다 먼저 봐야 할 것은?
  5. c를 쓰는 상황은?
정답 보기
  1. ni는 함수를 통과하고, si는 함수 안으로 들어간다.
  2. 실행을 멈춰 그 시점의 레지스터·메모리를 관찰하는 것이다.
  3. 두 문자열이 같다는 뜻이다.
  4. 역어셈블(disas)로 전체 분기 구조를 먼저 파악해야 한다.
  5. 관심 없는 루프·구간을 다음 정지점까지 한 번에 통과할 때이다.

5-2. 한눈에 보는 디버깅 루프

sequenceDiagram participant A as 분석가 participant G as gdb participant P as 프로세스 A->>G: break 설치 G->>P: 실행·정지 P-->>G: 레지스터·메모리 상태 G-->>A: 스냅샷 표시 A->>G: ni·si 한 칸 G->>P: 재개

읽는 법: 멈춤→스냅샷→한 칸의 루프입니다. 매 정지마다 eax와 분기 조건을 기록하면 전체 흐름이 복원됩니다.

6. 흔한 실수

  • ASLR 때문에 주소가 매번 바뀌는데 하드코딩한 브레이크포인트를 재사용하는 경우. 함수명·오프셋 기준을 쓴다.
  • si로 라이브러리 내부까지 들어가 길을 잃는 경우
