시스템 Level 5 장(chapter)

Metasploit 기초

취약점 검증 프레임워크 기본 흐름을 익힌다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • search → use → show options → set → run
  • 허가된 실습 VM에서만 실행
  • 검증 목적: 영향도 증명, 범위 준수

2. 핵심 개념

  • search → use → show options → set → run
  • 허가된 실습 VM에서만 실행
  • 검증 목적: 영향도 증명, 범위 준수

2-2. 동작 원리 심화: 검증 조립 라인

Metasploit은 찾기→고르기→맞추기→실행의 조립 라인입니다. search로 모듈을 찾고, use로 올리고, show options으로 빈칸을 확인하고, set으로 채운 뒤 run합니다. 목적은 파괴가 아니라 영향도 증명입니다.

flowchart TD S["search
모듈 검색"] --> U["use
모듈 선택"] U --> O["show options
필수값 확인"] O --> T["set RHOSTS 등
범위 내 대상"] T --> R["run·exploit
검증 실행"] R --> V["결과 기록
영향도 증명"]

읽는 법: 빈칸(show options)을 다 채우기 전에는 실행하지 않습니다. RHOSTS가 범위를 벗어나면 즉시 중단입니다.

2-3. 모듈 3종

모듈용도
exploit취약점 실행·세션 획득
auxiliary스캔·정보수집
post점유 후 추가 작업

3. 예제

search vsftpd / use ... / show options (실습)

3-2. 심화 예제: 검증 세션(실습 VM)

msfconsole -q
# 1) 모듈 검색·선택 (실습 대상 버전용)
search vsftpd
use exploit/unix/ftp/vsftpd_234_backdoor
# 2) 옵션 확인·설정 (RHOSTS는 실습망만!)
show options
set RHOSTS 실습호스트
set RPORT 21
# 3) 실행 전 범위 재확인 후 run
# check → run → sessions -l
# 4) 세션 정리: exit, 작업 로그 저장

4. 실습

  1. 옵션 설정 과정을 기록한다.
  2. 실행 전 범위·대상·금지행위를 체크한다.
  3. 검증 결과를 캡처와 함께 기록한다.
  4. 세션 정리 절차를 따른다.
  5. 영향도를 한 줄로 요약한다.

5. 퀴즈

  1. 모듈 3종(exploit/auxiliary/post)의 차이는?
  2. 실행 전 확인할 것은?
  3. show options에서 봐야 할 것은?
  4. 검증 목적을 벗어난 사용이 문제인 이유는?
  5. 세션 정리까지 해야 하는 이유는?
정답 보기
  1. 실행·수집·점유 후 작업으로 단계가 다르다.
  2. 허가 범위·대상·금지행위이다.
  3. 필수값과 현재값, 특히 RHOSTS이다.
  4. 무단 접근·파괴로 법적 문제가 되기 때문이다.
  5. 좀비 세션이 남으면 오작동·추적 문제가 생기기 때문이다.

5-2. 한눈에 보는 검증 흐름

sequenceDiagram participant A as 검증자 participant M as msfconsole participant T as 실습 대상 A->>M: search·use·set M->>T: 범위 내 검증 실행 T-->>M: 결과 반환 M-->>A: 영향도 기록

읽는 법: 설정→실행→기록의 고리입니다. 기록 없는 실행은 없었던 일과 같습니다.

6. 흔한 실수

  • RHOSTS를 범위 밖으로 넓히는 경우. 계약 위반이다.
  • 옵션 미확인 실행으로 엉뚱한 대상을 건드리는 경우
