웹 Level 4 장(chapter)

파일 업로드 취약점

업로드 기능을 통한 웹셸 공격과 방어법을 배운다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • 확장자 검증 우회: 대소문자, .phtml, 이중확장자
  • Content-Type 위조 가능 → 확장자로만 판단 금지
  • 실행권한 분리 + 저장경로 비공개 + 확장자 화이트리스트

2. 핵심 개념

  • 확장자 검증 우회: 대소문자, .phtml, 이중확장자
  • Content-Type 위조 가능 → 확장자로만 판단 금지
  • 실행권한 분리 + 저장경로 비공개 + 확장자 화이트리스트

2-2. 동작 원리 심화: 업로드가 실행으로 이어지는 길

업로드 자체는 파일 저장일 뿐입니다. 문제는 저장된 파일이 웹 경로로 실행될 때 생깁니다. 공격자는 검증 허점을 뚫고 스크립트를 올린 뒤, 그 URL에 직접 접속해 서버 권한으로 코드를 실행합니다.

flowchart TD U["파일 선택·전송"] --> V["서버 검증
확장자·MIME·매직"] V --> S["저장
웹루트 vs 외부"] S --> X{"URL로 실행 가능한가"} X -->|예| RCE["웹셸 실행
서버 장악"] X -->|아니오| SAFE["다운로드만 가능"]

읽는 법: 검증(V)과 저장 위치(S), 실행 가능 여부(X) 세 관문이 모두 뚫려야 공격이 성립합니다. 방어는 세 곳에 각각 둡니다.

2-3. 우회 vs 대응표

우회 시도원리대응
shell.phtml·.phar해석기로 실행되는 확장자확장자 화이트리스트
shell.jpg.php이중 확장자마지막 확장자가 아닌 허용 목록 대조
SHELL.PHP대소문자소문자 정규화 후 검사
MIME 위조Content-Type은 선언일 뿐매직바이트+확장자 함께 검사

3. 예제

shell.phtml 업로드 → 실행 경로 접근 (실습 환경에서만)

3-2. 심화 예제: 허용/차단 매트릭스(실습 앱)

# 확장자별 업로드 시도 후 상태코드·응답 기록
for ext in jpg png php phtml phar "jpg.php" "PHP" "php%00.jpg"; do
  echo -n "$ext : "
  curl -s -o /dev/null -w "%{http_code}\n" -F "f=@test.$ext" http://실습호스트/upload
done
# 업로드된 파일의 실제 접근 가능 여부 확인
curl -s -o /dev/null -w "%{http_code}\n" http://실습호스트/uploads/test.phtml
# 저장 경로가 웹루트 밖인지, 실행 비트가 꺼져 있는지 점검

4. 실습

  1. 확장자별 업로드 허용/차단 표를 만들어본다.
  2. 차단된 케이스의 응답(상태코드·메시지)을 기록한다.
  3. 업로드 디렉토리에 실행 권한이 있는지 확인한다.
  4. 화이트리스트+매직바이트 검사를 적용한 뒤 표를 다시 그린다.
  5. 안전한 저장 설계(무작위 파일명·웹루트 분리)를 한 페이지로 정리한다.

5. 퀴즈

  1. 안전한 저장 방법 2가지는?
  2. MIME 검사가 부족한 이유는?
  3. 이중 확장자가 위험한 이유는?
  4. 업로드 파일을 웹루트 밖에 두는 이유는?
  5. 무작위 파일명으로 저장하는 이유는?
정답 보기
  1. 확장자 화이트리스트와 실행 권한 분리(웹루트 밖 저장·스크립트 실행 차단)이다.
  2. Content-Type은 클라이언트 선언이라 위조가 자유롭기 때문이다.
  3. 서버·미들웨어가 앞 확장자가 아닌 뒤 확장자로 해석할 수 있기 때문이다.
  4. URL로 직접 접근해도 실행되지 않게(다운로드 스크립트 경유) 하기 위해서이다.
  5. 공격자가 업로드 경로를 예측해 직접 접근하는 것을 막기 위해서이다.

5-2. 한눈에 보는 방어 3관문

sequenceDiagram participant A as 공격자 participant V as 검증 participant S as 저장소 participant W as 웹 서버 A->>V: shell.phtml 전송 V->>V: 화이트리스트 대조 V-->>A: 거부·로그 V->>S: 허용분만 무작위명 저장 S->>W: 실행 차단 설정 W-->>A: 직접 접근해도 실행 불가

읽는 법: 검증→저장→실행 차단을 모두 통과해야 안전합니다. 하나라도 빠지면 우회 경로가 됩니다.

6. 흔한 실수

  • 블랙리스트(php만 차단) 방식. phtml·phar 등 해석 가능한 확장자가 그대로 뚫린다.
  • 원본 파일명 그대로 저장. 경로 예측 + 한글·특수문자 이슈까지 겹친다.
