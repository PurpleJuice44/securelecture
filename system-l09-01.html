시스템 Level 9 장(chapter)

시스템 진단 실전

점검→보고 흐름으로 진단한다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • 자산 파악 → 설정 점검 → 결과 정리
  • 명령 출력 캡처와 근거 기록
  • 위험도별 우선순위 제안

2. 핵심 개념

  • 자산 파악 → 설정 점검 → 결과 정리
  • 명령 출력 캡처와 근거 기록
  • 위험도별 우선순위 제안

2-2. 동작 원리 심화: 진단 3단계

진단은 자산 파악→설정 점검→결과 정리의 3단계입니다. 무엇을 지키는지 모르면 점검할 수 없고, 근거 없이 적으면 보고서가 안 됩니다. 명령 출력 캡처가 곧 증거입니다.

flowchart TD A["자산 파악
호스트·서비스 목록"] --> C["설정 점검
L0~L8 기법 총동원"] C --> E["증거 수집
출력 캡처"] E --> R["위험도 산정
상·중·하"] R --> P["보고·제안"]

읽는 법: 점검은 기술, 보고는 설득입니다. 근거 없는 주장은 보고서에서 지웁니다.

2-3. 산출물표

단계산출물
자산 파악자산 목록·담당자
설정 점검점검표+명령 출력
결과 정리위험도별 발견·조치안

3. 예제

점검표 양식으로 실습 VM 1대 진단

3-2. 심화 예제: 진단 세션 기록법

# script 명령으로 세션 전체 기록 (실습 VM)
script diag_$(date +%F).log
ss -tlnp
sudo ufw status verbose
find / -xdev -type f -perm -o+w 2>/dev/null | head
grep -v -E "nologin|false" /etc/passwd
exit  # 기록 종료
# 포인트: 명령+출력+시각이 한 파일에 남는다

4. 실습

  1. 진단 보고서 1건을 작성한다.
  2. 자산 목록을 먼저 만든다.
  3. 점검표 항목마다 명령 출력을 붙인다.
  4. 위험도를 매기고 근거를 적는다.
  5. 조치안을 단기·중기로 나눈다.

5. 퀴즈

  1. 점검 3단계는?
  2. 보고서 작성 팁은?
  3. 자산 파악이 먼저인 이유는?
  4. 캡처가 필요한 이유는?
  5. 위험도 산정 기준 2가지는?
정답 보기
  1. 자산 파악→설정 점검→결과 정리이다.
  2. 재현 가능한 명령·출력·근거 중심이다.
  3. 지킬 것을 알아야 점검 범위가 정해지기 때문이다.
  4. 주장마다 증거가 있어야 신뢰되기 때문이다.
  5. 악용 가능성과 비즈니스 영향이다.

5-2. 한눈에 보는 진단 흐름

sequenceDiagram participant A as 진단자 participant S as 대상 VM participant R as 보고서 A->>S: 자산·점검 수행 S-->>A: 출력·캡처 A->>R: 위험도·조치안 정리 R-->>A: 검토·제출

읽는 법: 손(점검)과 입(보고)이 따로 놉니다. 점검만 하고 보고를 안 하면 한 일이 증발합니다.

6. 흔한 실수

  • 자산 파악 없이 점검부터 하는 경우. 범위가 흔들린다.
  • 출력 없이 결론만 적는 경우
