리버싱 Level 10 장(chapter)

리버싱 프로젝트

분석 보고서를 포트폴리오로 마무리한다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • 대상 선정(실습용 crackme)
  • 분석 과정 기록(캡처 포함)
  • 대응·완화방안 제언

2. 핵심 개념

  • 대상 선정(실습용 crackme)
  • 분석 과정 기록(캡처 포함)
  • 대응·완화방안 제언

2-2. 동작 원리 심화: 포트폴리오 보고서 구조

프로젝트 보고서는 따라 하면 같은 결론에 닿는 문서입니다. 환경→방법→발견→대응의 4기둥에 증거(캡처·해시)를 붙입니다.

flowchart TD T["대상 선정
실습 crackme"] --> E["환경 기록
OS·도구 버전"] E --> M["방법
정적→동적 순서"] M --> F["발견
분기·로직·근거"] F --> C["대응 제언
완화방안"] C --> A["부록
해시·스크립트"]

읽는 법: 위에서 아래로가 보고서 목차입니다. 환경이 빠지면 재현이 불가해 보고서 가치가 반감합니다.

2-3. 평가 관점표

관점좋은 보고서나쁜 보고서
재현성명령·출력 그대로결과만 있고 과정 없음
근거주소·값 명시느낌 서술
윤리실습 범위 명시출처·범위 불명

3. 예제

보고서: 개요 → 분석환경 → 상세분석 → 결론

3-2. 심화 예제: 목차별 작성 포인트

# 개요: 대상·목적·범위를 5줄로 (실습용 crackme 명시)
# 분석환경: OS, gdb/Ghidra 버전, 대상 해시값
sha256sum crackme
# 상세분석: 단계별 명령+출력+해석 (캡처 첨부)
# 결론: 핵심 로직 3줄 요약 + 완화방안(난독화·무결성 검사 등)
// 대응 제언 예시: 정답 하드코딩 금지, 서버 검증으로 이전

4. 실습

  1. 분석 보고서 1건을 위 목차로 작성한다.
  2. 환경 섹션에 도구 버전·대상 해시를 포함한다.
  3. 상세분석의 각 주장에 주소·값을 붙인다.
  4. 대응 제언을 개발자 관점에서 3개 적는다.
  5. 동료가 재현해보고 피드백을 받는다.

5. 퀴즈

  1. 보고서에 반드시 들어갈 것은?
  2. 합법 범위 준수의 의미는?
  3. 환경 기록이 필요한 이유는?
  4. 좋은 대응 제언의 조건은?
  5. 포트폴리오에 싣기 전 확인할 것은?
정답 보기
  1. 환경·재현 가능한 과정·근거·결론이다.
  2. 실습용 대상·허가된 범위에서만 분석하고 상용 보호를 건드리지 않는 것이다.
  3. 버전·환경이 다르면 결과가 달라져 재현이 불가하기 때문이다.
  4. 구체적이고 실행 가능하며, 개발 비용을 고려한 것이다.
  5. 민감정보·무단 대상 포함 여부와 재현 가능성이다.

5-2. 한눈에 보는 마무리 흐름

sequenceDiagram participant A as 작성자 participant R as 검토자 participant P as 포트폴리오 A->>R: 초안 제출 R-->>A: 재현·근거 보완 요청 A->>R: 수정본 제출 R-->>P: 공개 승인

읽는 법: 검토는 문장이 아니라 재현 가능성을 봅니다. 남이 따라 해서 같은 결론이면 합격입니다.

6. 흔한 실수

  • 캡처만 잔뜩 붙이고 명령·해석이 없는 경우
  • 실습 범위를 명시하지 않아 오해를 사는 경우
