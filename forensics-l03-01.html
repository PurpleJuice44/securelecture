포렌식 Level 3 장(chapter)

디스크 이미징

원본 디스크를 이미지로 안전하게 복사한다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • dd/dcfldd로 비트단위 복사
  • 취득 전후 해시 기록
  • 이미지는 분석용, 원본은 봉인

2. 핵심 개념

  • dd/dcfldd로 비트단위 복사
  • 취득 전후 해시 기록
  • 이미지는 분석용, 원본은 봉인

2-2. 동작 원리 심화: 비트 단위 복사의 의미

파일 복사와 이미징은 다릅니다. 파일 복사는 보이는 파일만 옮기지만, 이미징은 빈 공간·삭제된 영역·슬랙까지 포함한 섹터 전체를 복사합니다. 삭제 파일 복원이 가능한 이유가 여기에 있습니다.

flowchart TD D["원본 디스크
파일+빈공간+삭제영역"] --> RO["읽기 전용 연결
Write Blocker"] RO --> CP["섹터 단위 복사
dd·dcfldd·EWF"] CP --> H["전후 해시 기록
SHA256"] H --> V{"해시 일치?"} V -->|예| M["이미지 마운트·분석
원본은 봉인"] V -->|아니오| RE["재취득"]

읽는 법: 해시 일치가 이미징의 합격선입니다. 불일치 이미지는 분석에 쓰지 않고 처음부터 다시 취득합니다.

2-3. 취득 방식 비교

방식장점주의
dd (raw)단순·호환성 최고압축·메타 없음, 용량 큼
dcfldd진행률·해시 동시 기록옵션 숙지 필요
EWF (E01)압축·CoC 메타 내장전용 도구 필요

3. 예제

dd if=/dev/sdb of=case.dd bs=4M status=progress  (실습 디스크만)

3-2. 심화 예제

# 실습용 USB(본인 소유)에서만 실행할 것. 디바이스명 필히 확인!
lsblk
# 해시와 함께 이미징 (취득 중 해시 동시 계산)
dcfldd if=/dev/sdX of=case.dd bs=4M hash=sha256 hashlog=case.hashlog statusinterval=16
# 취득 후 검증: 원본과 이미지 해시 비교
sha256sum /dev/sdX case.dd
# 이미지를 읽기 전용으로 마운트해 내용 확인
mkdir -p mnt && mount -o ro,loop case.dd mnt && ls mnt && umount mnt

4. 실습

  1. lsblk로 실습 디스크 장치명을 확정한다(오지정 금지).
  2. dcfldd로 이미징하며 해시로그를 남긴다.
  3. 원본·이미지 해시를 비교하고 CoC에 기록한다.
  4. 이미지를 ro·loop 마운트해 파일 목록을 확인한다.
  5. 이미지에서 삭제 파일 1개를 카빙(foremost)으로 복원해본다.

5. 퀴즈

  1. 이미징을 하는 이유는?
  2. 해시를 기록하는 이유는?
  3. 파일 복사와 이미징의 차이는?
  4. if/of를 뒤바꾸면 무슨 일이 생기는가?
  5. EWF(E01)가 raw보다 유리한 점은?
정답 보기
  1. 원본을 건드리지 않고 삭제 영역까지 포함한 완전한 사본으로 분석하기 위해서이다.
  2. 취득 전후 동일함을 증명해 증거 무결성을 보장하기 위해서이다.
  3. 파일 복사는 보이는 파일만, 이미징은 빈 공간·삭제 영역까지 섹터 단위로 복사한다.
  4. 빈 디스크 내용이 원본을 덮어써 증거가 파괴된다. 치명적 실수이므로 장치명 확인이 필수이다.
  5. 압축으로 용량을 줄이고 해시·CoC 메타를 파일 안에 함께 보관할 수 있다.

6. 흔한 실수

  • of=/dev/sdX로dest를 잘못 적어 원본을 덮어쓰는 사고. oflag=direct 확인 습관과 장치명 이중 점검이 필수이다.
  • 마운트된 상태의 디스크를 이미징해 도중 변경으로 해시가 어긋나는 경우
