🔍 리버싱

바이너리를 읽는 눈. 어셈블리부터 crackme까지.

분야 아키텍처: 바이너리를 여는 두 개의 눈

리버싱은 실행하지 않고 읽는 정적 분석과 실행하며 관찰하는 동적 분석의 쌍안경입니다. 두 눈이 합쳐질 때 보호막(패킹·안티디버깅)이 벗겨집니다.

flowchart TD B["대상 바이너리
ELF·PE"] --> S["정적 분석
strings·objdump·역어셈블"] B --> D["동적 분석
gdb·strace·디버거"] S --> ST["구조 파악
함수·문자열·호출관계"] D --> DY["행위 관찰
레지스터·메모리·syscall"] ST --> P["보호막 식별
UPX·안티디버깅"] DY --> P P --> U["언패킹·우회"] U --> C["crackme 풀이
로직 복원·패치"]

읽는 법: 위에서 아래로가 분석 순서입니다. 정적과 동적은 번갈아 수행하며 서로의 가설을 검증합니다.

학습 로드맵

숫자 읽기에서 시작해 CPU 동작을 이해하고, 도구를 거쳐 보호막을 벗긴 뒤 실전 crackme로 마무리합니다.

flowchart LR R0["L0 수와 어셈블리"] --> R1["L1 레지스터·스택"] R1 --> R2["L2 정적 분석 도구"] R2 --> R3["L3 동적 분석 gdb"] R3 --> R4["L4 crackme 패치"] R4 --> R6["L6 UPX 패킹"] R6 --> R7["L7 안티디버깅"] R7 --> R8["L8 악성코드 1차 분석"] R8 --> R9["L9 실전 crackme"] R9 --> R10["L10 리버싱 프로젝트"]

읽는 법: 왼쪽부터 순서대로 학습하세요. L2와 L3은 짝을 이뤄 서로를 보완합니다.
