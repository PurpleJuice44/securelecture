리버싱 Level 2 장(chapter)

정적 분석 도구

실행 없이 바이너리 정보를 추출한다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • file·strings로 1차 정보 수집
  • Ghidra로 디컴파일 읽기
  • 의심 문자열(URL·비밀번호) 추출

2. 핵심 개념

  • file·strings로 1차 정보 수집
  • Ghidra로 디컴파일 읽기
  • 의심 문자열(URL·비밀번호) 추출

2-2. 동작 원리 심화: 실행 없이 읽는 순서

정적 분석은 겉→속 순서로 파고듭니다. 파일 형식 확인→문자열 긁기→심볼·섹션 구조→디컴파일 순이며, 앞 단계에서 단서가 나오면 뒤를 깊게 팝니다.

flowchart TD F["file 명령
형식·아키텍처"] --> S["strings
URL·비밀번호·에러문구"] S --> Y["심볼·섹션
nm·readelf·함수 목록"] Y --> G["Ghidra 디컴파일
C 유사코드"] G --> J{"핵심 로직 발견?"} J -->|예| D["동적 분석으로 검증
L3로 이동"] J -->|아니오| P["패킹 의심
L6으로 이동"]

읽는 법: 위에서 아래로가 표준 동선입니다. strings가 비어 있으면 패킹을, 함수가 보이면 동적 검증을 의심합니다.

2-3. 도구별 역할

도구보는 것명령 예시
file형식·아키텍처file a.out
strings평문 단서strings -n 6 a.out
nm·readelf심볼·섹션nm -D a.out
objdump역어셈블objdump -d -M intel a.out
Ghidra디컴파일CodeBrowser 임포트

3. 예제

file a.out
strings a.out | grep -i 'pass\|http' | head

3-2. 심화 예제: 5분 트리아지

# 1) 정체 파악 (10초)
file crackme && checksec --file=crackme 2>/dev/null
# 2) 문자열 단서 (1분)
strings -n 6 crackme | grep -i -E "pass|flag|http|fail|success| Congrat" | head -20
# 3) 심볼·호출관계 (1분)
nm -D crackme | head -20
objdump -d -M intel crackme | grep -E "call.*(strcmp|scanf|printf)" | head
# 4) 의심 함수만 Ghidra로 (2분)

4. 실습

  1. 실습 바이너리에서 URL 3개를 추출한다.
  2. 성공·실패 메시지를 찾아 비교 함수 후보를 좁힌다.
  3. 호출된 비교 함수(scanf·strcmp 계열) 목록을 적는다.
  4. Ghidra에 올려 의심 함수 1개를 디컴파일로 읽는다.
  5. 정적 가설 1줄을 적고 L3에서 검증할 포인트를 정한다.

5. 퀴즈

  1. strings의 용도는?
  2. 정적분석의 한계는?
  3. strings 결과가 텅 비면 의심하는 것은?
  4. checksec이 보여주는 보호기법 3가지는?
  5. 정적 가설을 동적으로 검증해야 하는 이유는?
정답 보기
  1. 바이너리 속 평문(문자열)을 뽑아 URL·메시지 등 단서를 찾는 것이다.
  2. 실행하지 않으므로 패킹·난독화·실행 시 복호화 구간은 보이지 않는다.
  3. 패킹·암호화를 의심하고 언패킹(L6)으로 분기한다.
  4. NX·Canary·PIE(ASLR) 등이다.
  5. 정적 추론은 가설일 뿐, 실제 분기를 타는지 실행으로 확인해야 하기 때문이다.

5-2. 한눈에 보는 트리아지 흐름

sequenceDiagram participant A as 분석가 participant F as file·strings participant O as objdump participant G as Ghidra A->>F: 1차 수집 F-->>A: 형식·단서 A->>O: 의심 함수 역어셈블 O-->>A: 분기 구조 A->>G: 핵심 함수 디컴파일 G-->>A: 로직 가설

읽는 법: 가벼운 도구에서 무거운 도구 순서입니다. Ghidra는 마지막에, 그것도 의심 함수만 봅니다.

6. 흔한 실수

  • 바이너리 전체를 Ghidra로 읽으려다 길을 잃는 경우. strings로 좁힌 뒤 본다.
  • 스트립된 바이너리에서 함수명을 믿는 경우. 주소·호출관계로 식별한다.
