포너블 Level 5 장(chapter)

ASLR 우회와 릭

주소 랜덤화를 정보유출로 극복한다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • ASLR=매 실행 주소 변경
  • leak으로 실제 주소 1개 확보
  • base + offset으로 목표 계산

2. 핵심 개념

  • ASLR=매 실행 주소 변경
  • leak으로 실제 주소 1개 확보
  • base + offset으로 목표 계산

2-2. 동작 원리 심화: 랜덤을 고정으로 바꾸기

ASLR은 매 실행마다 주소를 바꿔 하드코딩을 무력화합니다. 하지만 상대 거리는 그대로입니다. 실제 주소 1개만 새어나오면(leak), base를 역산해 모든 목표 주소를 계산할 수 있습니다.

flowchart TD L["leak 확보
puts GOT 출력 등"] --> K["알려진 오프셋
puts offset"] K --> B["base 계산
leak - offset"] B --> T["목표 계산
base + system offset"] T --> R["ROP 체인에 대입"] F["실패 시"] --> L2["다른 leak 지점 탐색"]

읽는 법: leak 1개가 기준점입니다. 기준점에서 상대 거리로 모든 주소를 복원하므로 ASLR이 무력화됩니다.

2-3. 계산표

값구하는 법예시
leak출력 유출0x7f...a40
puts 오프셋libc readelf0x80ed0
baseleak - 오프셋계산
systembase + 오프셋체인 대입

3. 예제

leak 주소 − 알려진 오프셋 = base (개념)

3-2. 심화 예제: 숫자 연습(개념값)

# leak = 0x7ffff7a5b40 (puts 실제 주소)
# puts 오프셋 = 0x80ed0, system 오프셋 = 0x4f550 (libc 버전별 상이)
leak   = 0x7ffff7a5b40
base   = leak - 0x80ed0
system = base + 0x4f550
print(hex(base), hex(system))
# 포인트: 같은 libc 파일에서 오프셋을 구해야 한다
# readelf -s libc.so.6 | grep -E " puts| system"

4. 실습

  1. 릭→계산 과정을 숫자로 연습한다.
  2. libc 버전을 고정하고 오프셋 2개를 구한다.
  3. leak 값을 바꿔 base·system을 재계산한다.
  4. 계산 결과를 ROP 체인에 대입하는 그림을 그린다.
  5. PIE와 ASLR의 차이를 한 줄로 정리한다.

5. 퀴즈

  1. leak이 필요한 이유는?
  2. base+offset 계산법은?
  3. 다른 libc 버전 오프셋을 쓰면 생기는 일은?
  4. PIE와 ASLR의 차이는?
  5. leak 없이 ASLR을 뚫기 어려운 이유는?
정답 보기
  1. 랜덤화된 실제 주소의 기준점 1개가 있어야 상대 계산이 가능하기 때문이다.
  2. base = leak - 알려진 오프셋, 목표 = base + 목표 오프셋이다.
  3. 계산된 주소가 엉뚱한 곳을 가리켜 crash한다.
  4. ASLR은 전체 랜덤화 기법, PIE는 실행파일 자체를 위치 독립적으로 만든 것이다.
  5. 주소를 찍을 기준이 없어 확률 게임이 되기 때문이다.

5-2. 한눈에 보는 릭→계산

sequenceDiagram participant A as 공격자 participant P as 프로그램 A->>P: 출력 유발 입력 P-->>A: leak 주소 A->>A: base 역산 A->>A: system 계산 A->>P: 완성 체인 전송

읽는 법: 유출→계산→공격의 2단계 구조입니다. 유출이 막히면 이후 단계가 전부 무너집니다.

6. 흔한 실수

  • 서로 다른 libc 파일의 오프셋을 섞어 쓰는 경우
  • leak 값에 개행·널이 잘려 주소가 깨지는 경우
