리버싱 Level 9 장(chapter)

실전 crackme 풀이

정적+동적 분석을 연결해 풀이한다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • strings → Ghidra → gdb 순서
  • 입력 검증 루틴 역추적
  • 풀이 스크립트(python)로 정답 재현

2. 핵심 개념

  • strings → Ghidra → gdb 순서
  • 입력 검증 루틴 역추적
  • 풀이 스크립트(python)로 정답 재현

2-2. 동작 원리 심화: 정적+동적 연결 풀이

실전 풀이는 정적 가설과 동적 검증의 왕복입니다. strings로 후보를 좁히고, Ghidra로 로직을 읽고, gdb에서 입력별 분기를 확인한 뒤, 파이썬 스크립트로 정답을 재현합니다.

flowchart TD S["strings
후보 함수·메시지"] --> G["Ghidra
검증 루틴 판독"] G --> H["가설 수립
입력 변환식 추정"] H --> D["gdb 검증
분기·레지스터 확인"] D --> C{"가설 일치?"} C -->|아니오| G C -->|예| P["python 풀이 스크립트"] P --> W["Write-up"]

읽는 법: 가설→검증→수정 고리입니다. 한 번에 맞히려 하지 말고 고리를 빨리 도는 것이 실력입니다.

2-3. 검증 루틴 유형표

유형특징공략
직접 비교정답 문자열 내장strings·역참조 추적
변환 비교XOR·연산 후 비교역연산 스크립트
분할 검증여러 함수에 나눔호출 순서 재구성

3. 예제

정답 입력값을 스크립트로 자동 입력해 검증

3-2. 심화 예제: 풀이 스크립트 골격

# 1) Ghidra에서 읽은 변환식 재현 (예: 각 바이트 +1 후 비교)
enc = [0x42, 0x43, 0x44]  # 역어셈블에서 확인한 값
flag = "".join(chr(b - 1) for b in enc)
print(flag)
# 2) 자동 입력 검증
import subprocess
p = subprocess.run(["./crackme"], input=flag, capture_output=True, text=True)
print("성공" if "Success" in p.stdout else "실패")
# 3) 실패 시: gdb로 분기 재확인 후 변환식 수정

4. 실습

  1. crackme 1개를 풀이하고 Write-up을 작성한다.
  2. strings→Ghidra→gdb 각 단계의 산출물을 기록한다.
  3. 가설이 틀렸던 지점과 수정 과정을 남긴다.
  4. 풀이 스크립트로 정답을 재현한다.
  5. Write-up을 제3자가 따라 할 수 있는지 검증한다.

5. 퀴즈

  1. 풀이 순서를 말해본다
  2. Write-up 필수 항목은?
  3. 가설 검증에 gdb가 필요한 이유는?
  4. 스크립트 재현까지 해야 하는 이유는?
  5. 막혔을 때 돌아갈 지점은?
정답 보기
  1. strings → Ghidra → gdb → 스크립트 순이다.
  2. 환경·단계별 명령과 출력·가설 수정 과정·재현 스크립트이다.
  3. 정적 추론이 실제 분기와 같은지 실행으로 확인해야 하기 때문이다.
  4. 손풀이는 우연일 수 있고, 스크립트가 로직 이해의 증거이기 때문이다.
  5. 한 단계 앞이 아니라 strings·가설 원점으로 돌아가 전제를 의심한다.

5-2. 한눈에 보는 풀이 왕복

sequenceDiagram participant A as 풀이자 participant S as 정적 분석 participant D as 동적 검증 A->>S: 후보·가설 도출 S-->>A: 검증 루틴 추정 A->>D: 입력별 분기 확인 D-->>A: 일치·불일치 A->>A: 스크립트 재현

읽는 법: 정적과 동적을 번갈아 왕복합니다. 왕복 횟수가 실력이 아니라 왕복 속도와 기록이 실력입니다.

6. 흔한 실수

  • 정답 문자열만 뽑고 로직 이해를 건너뛰는 경우. 변형 문제에 무너진다.
  • Write-up 없이 풀이만 하고 끝내는 경우
