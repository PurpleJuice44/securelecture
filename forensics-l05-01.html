포렌식 Level 5 장(chapter)

메모리 포렌식

RAM 덤프에서 프로세스·연결을 복원한다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • Volatility로 프로세스 목록
  • 악성 프로세스(parent/시간) 식별
  • 네트워크 연결·주입 흔적

2. 핵심 개념

  • Volatility로 프로세스 목록
  • 악성 프로세스(parent/시간) 식별
  • 네트워크 연결·주입 흔적

2-2. 동작 원리 심화: 휘발성 증거의 우선순위

메모리는 전원을 끄면 사라집니다. 그래서 수집 순서(Order of Volatility)가 레지스터·캐시 → 메모리 → 디스크이며, 메모리 덤프는 디스크 이미징보다 먼저 수행합니다. 덤프 안에는 실행 중 프로세스·네트워크 연결·암호화 키처럼 디스크에 없는 정보가 들어 있습니다.

flowchart TD L["라이브 시스템
전원 유지"] --> D["메모리 덤프
WinPmem·LiME·AVML"] D --> H["덤프 해시 기록"] H --> P["프로파일 판별
imageinfo"] P --> PS["pslist·pstree
프로세스 계층"] PS --> NT["netscan
연결·소켓"] PS --> MJ["malfind·ldrmodules
인젝션 흔적"] NT --> AN["판정·타임라인 편입"] MJ --> AN

읽는 법: 덤프→프로파일→프로세스→연결·인젝션 순으로 좁혀갑니다. 프로파일이 틀리면 이후 결과가 전부 깨지므로 imageinfo를 먼저 확정합니다.

2-3. 의심 프로세스 판별 포인트

지표정상 예시의심 예시
부모-자식 관계explorer → chrome부모 없는 svchost, winword → powershell
경로C:\Windows\System32Temp·AppData에서 실행되는 시스템 이름
생성 시각부팅 직후 집중심야·단발성 생성 후 상주
연결브라우저의 443불명 프로세스의 외부 고포트 지속 연결

3. 예제

vol.py -f mem.raw --profile=Win7SP1x64 pslist

3-2. 심화 예제: 프로세스에서 인젝션까지

# 1) 프로파일 확정 (가장 먼저)
vol.py -f mem.raw imageinfo
# 2) 프로세스 계층과 시간축
vol.py -f mem.raw --profile=Win7SP1x64 pstree
vol.py -f mem.raw --profile=Win7SP1x64 psxview
# 3) 네트워크 연결 (누가 어디에 붙어 있나)
vol.py -f mem.raw --profile=Win7SP1x64 netscan
# 4) 코드 인젝션 흔적
vol.py -f mem.raw --profile=Win7SP1x64 malfind -D dump/
vol.py -f mem.raw --profile=Win7SP1x64 ldrmodules

4. 실습

  1. imageinfo로 프로파일을 확정한다.
  2. pstree에서 부모 없는 프로세스와 낯선 부모-자식 쌍을 3개 고른다.
  3. netscan으로 외부 연결 프로세스를 뽑아 2번과 대조한다.
  4. malfind 덤프를 strings로 살펴본다.
  5. 의심 프로세스 1개를 골라 4가지 지표(부모·경로·시각·연결) 근거를 적는다.

5. 퀴즈

  1. 메모리 분석이 필요한 경우는?
  2. pslist의 용도는?
  3. 덤프를 디스크 이미징보다 먼저 하는 이유는?
  4. 프로파일 판별을 먼저 해야 하는 이유는?
  5. malfind가 찾는 것은?
정답 보기
  1. 파일리스 악성코드·실행 중 연결·암호화 키처럼 디스크에 남지 않는 흔적을 볼 때이다.
  2. 메모리 속 프로세스 목록을 뽑아 PID·PPID·시작 시각을 확인하는 것이다.
  3. 메모리는 휘발성이라 전원이 꺼지거나 시간이 지나면 사라지기 때문이다.
  4. 프로파일(커널 구조 정의)이 틀리면 이후 모든 파싱 결과가 어긋나기 때문이다.
  5. 정상 이미지와 다른 메모리 보호 속성(RWX 사설 영역 등)의 인젝션 의심 코드이다.

5-2. 한눈에 보는 메모리 분석 파이프라인

sequenceDiagram participant A as 분석가 participant D as 메모리 덤프 participant V as Volatility participant J as 판정 A->>D: 해시 검증 후 적재 D-->>V: imageinfo V-->>A: 프로파일 확정 A->>V: pstree·netscan V-->>A: 프로세스·연결 목록 A->>V: malfind 심층 V-->>J: 인젝션 근거 J-->>A: 의심 프로세스 확정

읽는 법: 프로파일 확정 없이 심층 분석으로 건너뛰지 않습니다. 넓게 보고(프로세스) 좁게 찌르는(인젝션) 순서입니다.

6. 흔한 실수

  • 분석용 도구를 감염 시스템에서 직접 실행해 메모리를 오염시키는 경우. 덤프는 최소 개입 도 Dir로, 분석은 별도 머신에서 한다.
  • 프로파일 미확정 상태에서 모듈 결과를 해석해 오판하는 경우
