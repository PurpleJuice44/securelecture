포렌식 Level 6 장(chapter)

네트워크 포렌식 (pcap)

패킷 캡처에서 파일을 복원한다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • tshark/wireshark 필터(http, dns)
  • 파일 카빙: 전송된 파일 추출
  • C2 통신 패턴(주기적 비콘)

2. 핵심 개념

  • tshark/wireshark 필터(http, dns)
  • 파일 카빙: 전송된 파일 추출
  • C2 통신 패턴(주기적 비콘)

2-2. 동작 원리 심화: 스트림 재조립

패킷은 쪼개져서 옵니다. Wireshark의 Follow TCP Stream은 흩어진 패킷을 순서대로 이어 붙여 원래 대화(HTTP 요청·응답, 전송 파일)로 복원합니다. 암호화되지 않은 구간에서만 내용이 보이며, C2 비콘은 주기·크기의 규칙성으로 식별합니다.

flowchart TD P["pcap 입수"] --> S["통계 먼저
Conversations·Protocol Hierarchy"] S --> F["display filter
http·dns·ip.addr"] F --> B{"비콘 의심?
주기·크기 규칙성"} B -->|예| C2["C2 후보 격리
간격 히스토그램"] B -->|아니오| ST["스트림 재조립
Follow TCP Stream"] ST --> EX["파일 추출
Export Objects"] EX --> AN["추출물 분석
해시·시그니처"]

읽는 법: 전체 통계로 지도를 그린 뒤 필터로 좁히고, 스트림 재조립으로 실체를 꺼냅니다. 처음부터 패킷을 하나씩 읽지 않습니다.

2-3. 비콘 판별 체크리스트

특징정상 예시C2 의심
주기불규칙(사용자 행위)60초 고정 간격
크기다양함항상 같은 바이트
시간대업무 시간 집중24시간 균등·심야 포함
도메인유명 CDN·포털무작위 문자열·신규 등록

3. 예제

tshark -r cap.pcap -Y http -T fields -e http.host | sort | uniq -c

3-2. 심화 예제

# 1) 대화 통계: 누가 누구와 얼마나 주고받았나
tshark -r cap.pcap -q -z conv,ip
# 2) DNS 질의 Top (터널링·DGA 단서)
tshark -r cap.pcap -Y dns -T fields -e dns.qry.name | sort | uniq -c | sort -nr | head
# 3) HTTP 객체 추출 (전송 파일 복원)
tshark -r cap.pcap --export-objects http,extracted/
ls -l extracted/ && file extracted/*
# 4) 특정 IP의 주기성 확인 (비콘 간격)
tshark -r cap.pcap -Y "ip.addr==192.0.2.10" -T fields -e frame.time_epoch | awk 'NR>1{print $1-p} {p=$1}' | sort -n | uniq -c

4. 실습

  1. Conversations에서 바이트 수 상위 5개 대화를 뽑는다.
  2. HTTP 객체를 추출해 파일 1개를 복원하고 해시를 구한다.
  3. DNS 질의 Top 10에서 무작위 문자열 도메인을 찾는다.
  4. 의심 IP의 패킷 간격을 계산해 주기성을 판단한다.
  5. 복원 파일+비콘 근거를 한 페이지로 정리한다.

5. 퀴즈

  1. 비콘(Beacon)이란?
  2. 카빙이란?
  3. 스트림 재조립이 필요한 이유는?
  4. 암호화 구간(TLS)에서 볼 수 있는 것과 볼 수 없는 것은?
  5. 정상 업데이트 통신과 C2 비콘을 구분하는 방법은?
정답 보기
  1. 감염 단말이 C2 서버에 주기적으로 보내는 생존·명령대기 신호이다.
  2. 패킷·디스크 등 원시 데이터에서 의미 있는 단위(파일·대화)를 잘라 복원하는 것이다.
  3. 데이터가 여러 패킷에 쪼개져 전송되므로 순서대로 이어야 원래 내용이 되기 때문이다.
  4. SNI·証明서·크기·타이밍은 보이고, HTTP 본문·전송 파일 내용은 보이지 않는다.
  5. 주기·크기·시간대의 규칙성 3가지를 함께 본다. 셋 다 규칙적이면 C2 가능성이 높다.

5-2. 한눈에 보는 pcap 분석 흐름

sequenceDiagram participant A as 분석가 participant T as tshark participant W as Wireshark participant F as 추출물 A->>T: 대화 통계·DNS Top T-->>A: 의심 IP·도메인 A->>W: 스트림 재조립 W-->>F: 전송 파일 복원 F-->>A: 해시·시그니처 판정

읽는 법: 명령행(tshark)으로 좁히고 GUI(Wireshark)로 확인하는 분업이 효율적입니다. 추출물은 반드시 해시부터 구합니다.

6. 흔한 실수

  • 캡처 시간과 공격 시간의 타임존을 맞추지 않아 인과를 뒤집는 경우
  • 재전송·순서뒤바뀜 패킷을 중복 집계해 통계를 부풀리는 경우
