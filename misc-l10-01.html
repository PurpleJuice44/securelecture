Misc Level 10 장(chapter)

종합 프로젝트

분야를 연결한 포트폴리오를 만든다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • 주제 1개 + 분야 2개 이상 연결
  • GitHub 정리(목차·코드·보고서)
  • 발표 5분 구성

2. 핵심 개념

  • 주제 1개 + 분야 2개 이상 연결
  • GitHub 정리(목차·코드·보고서)
  • 발표 5분 구성

2-2. 동작 원리 심화: 연결이 실력이다

종합 프로젝트는 분야 2개 이상을 엮은 하나의 이야기입니다. 예: 로그 수집(시스템)→정규식 추출(Misc)→타임라인 보고(포렌식). 단일 기술 나열이 아니라 연결이 평가받습니다.

flowchart TD T["주제 선정
작고 구체적으로"] --> F["분야 2개 연결
예: 로그+정규식"] F --> I["구현·수집"] I --> R["보고서·코드 정리"] R --> P["GitHub 공개"] P --> V["5분 발표"]

읽는 법: 주제→연결→구현→공개→발표의 순서입니다. 연결 지점이 프로젝트의 개성입니다.

2-3. 평가표

관점좋음나쁨
연결분야가 이야기를 이룸기술 나열
재현코드·데이터 포함결과만 있음
발표문제→해결 5분시간 초과·두서없음

3. 예제

예: 로그분석+정규식+보고서 패키지

3-2. 심화 예제: 저장소 구조

my-project/
  README.md        # 문제→해결 10줄 + 실행법
  src/             # 스크립트 (요구사항·버전 명시)
  data-sample/     # 재현용 샘플 (민감정보 제외)
  docs/            # 보고서·발표자료
  # 포인트: 클론 후 5분 안에 데모가 돌아가야 한다

4. 실습

  1. 프로젝트 1건을 완성한다.
  2. 주제를 한 문장으로 적는다.
  3. 분야 연결점을 그림으로 그린다.
  4. 저장소를 위 구조로 정리한다.
  5. 5분 발표를 리허설한다.

5. 퀴즈

  1. 좋은 포트폴리오의 조건은?
  2. 발표 구성 3단계는?
  3. 분야 연결이 중요한 이유는?
  4. 샘플 데이터가 필요한 이유는?
  5. 5분 제한의 의도는?
정답 보기
  1. 재현 가능하고 연결이 있는 것이다.
  2. 문제→해결→교훈이다.
  3. 실전 문제는 분야를 넘나들기 때문이다.
  4. 남이 돌려봐야 신뢰되기 때문이다.
  5. 핵심만 말하는 훈련이다.

5-2. 한눈에 보는 마무리

sequenceDiagram participant A as 작성자 participant R as 검토자 A->>R: 저장소 공개 R-->>A: 재현·이해 피드백 A->>R: 발표 리허설 R-->>A: 시간·구성 승인

읽는 법: 공개→피드백→발표의 순서입니다. 남의 눈을 거치지 않은 포트폴리오는 미완성입니다.

6. 흔한 실수

  • 거창한 주제로 시작해 완성을 못하는 경우. 작게 잡고 끝낸다.
  • 민감정보를 샘플에 섞는 경우
