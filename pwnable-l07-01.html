포너블 Level 7 장(chapter)

Heap 기초

malloc/free와 힙 청크 개념을 이해한다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • malloc(할당)/free(해제) 짝 맞추기
  • use-after-free/double-free 개념
  • 힙은 메타데이터(크기 등)와 함께 관리

2. 핵심 개념

  • malloc(할당)/free(해제) 짝 맞추기
  • use-after-free/double-free 개념
  • 힙은 메타데이터(크기 등)와 함께 관리

2-2. 동작 원리 심화: 힙의 생명주기

힙은 할당(malloc)→사용→해제(free)의 생명주기를 가집니다. 청크 앞에는 크기 등 메타데이터가 붙고, 해제된 청크는 재사용 목록에 들어갑니다. 이 고리가 어긋나면 UAF·double-free가 터집니다.

flowchart TD M["malloc
청크 할당"] --> U["사용
읽기·쓰기"] U --> F["free
해제·목록 등록"] F --> N["포인터 NULL 처리?"] N -->|예| S["안전 종료"] N -->|아니오| V["UAF 위험
다음 장 공략"] F2["double free"] --> C["목록 오염
중복 할당"]

읽는 법: 해제 후 포인터를 비우지 않으면 죽은 청크를 계속 가리킵니다. 그것이 UAF의 씨앗입니다.

2-3. 힙 취약점 3종

취약점원인결과
UAF해제 후 사용재할당 내용 장악
double-free두 번 해제할당자 상태 오염
heap overflow청크 경계 초과 쓰기메타데이터 변조

3. 예제

할당→해제→사용 순서도 그리기

3-2. 심화 예제: 생명주기 코드로 보기

char *p = malloc(32);   // 1) 할당: 청크+메타데이터
strcpy(p, "hello");      // 2) 사용
free(p);                 // 3) 해제: 재사용 목록행
// p = NULL;             // ← 이 한 줄이 없으면 UAF!
strcpy(p, "evil");       // 4) 해제 후 사용 (취약)
// double-free 예시
// free(p); free(p);     // 두 번 해제 (취약)

4. 실습

  1. UAF 상황을 순서도로 그려본다.
  2. 위 코드에서 취약 줄을 표시하고 패치를 적는다.
  3. malloc/free 짝을 표로 맞춰본다.
  4. 청크+메타데이터 그림을 그린다.
  5. double-free가 할당자를 망치는 이유를 한 줄로 적는다.

5. 퀴즈

  1. UAF란?
  2. double-free의 위험은?
  3. 해제 후 NULL 대입이 막는 것은?
  4. 힙 메타데이터가 노려지는 이유는?
  5. 스택 BOF와 힙 취약점의 차이는?
정답 보기
  1. 해제된 메모리를 계속 사용하는 것이다.
  2. 할당자 목록이 오염되어 같은 메모리가 중복 배분된다.
  3. 죽은 포인터 사용(UAF)을 막는다.
  4. 크기·링크를 속이면 할당 흐름 자체를 조작할 수 있기 때문이다.
  5. 스택은 복귀주소 직접 덮기, 힙은 생명주기·메타 조작이다.

5-2. 한눈에 보는 생명주기

sequenceDiagram participant P as 프로그램 participant H as 힙 할당자 P->>H: malloc 요청 H-->>P: 청크 반환 P->>H: free 반환 H-->>H: 목록 등록 P->>P: NULL 대입 (안전)

읽는 법: 빌려쓰고 반납하고 명부에서 지우기까지가 한 사이클입니다. 마지막 줄이 빠지면 사고가 납니다.

6. 흔한 실수

  • free만 하고 NULL을 빼먹는 경우. 리뷰 체크리스트 1순위이다.
  • 에러 경로에서만 해제가 빠져 누수·이중해제가 생기는 경우
