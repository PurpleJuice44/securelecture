Misc Level 8 장(chapter)

Write-up 작성법

풀이를 재현 가능하게 기록한다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • 문제 분류 → 관찰 → 가설 → 풀이 → 스크립트
  • 스크린샷+코드 포함
  • 실패 과정도 자산

2. 핵심 개념

  • 문제 분류 → 관찰 → 가설 → 풀이 → 스크립트
  • 스크린샷+코드 포함
  • 실패 과정도 자산

2-2. 동작 원리 심화: 재현 가능성의 3요소

좋은 Write-up은 환경·명령·출력이 다 있어야 합니다. 같은 명령을 치면 같은 결과가 나오는 문서가 재현 가능하고, 실패 과정까지 있어야 다음 사람이 같은 함정에 안 빠집니다.

flowchart TD C["분류·관찰"] --> H["가설 수립"] H --> P["풀이 시도"] P --> F{"성공?"} F -->|아니오| L["실패 기록
자산으로 축적"] L --> H F -->|예| W["스크립트·캡처 정리"]

읽는 법: 실패를 지우지 않습니다. 실패 로그가 다음 가설의 재료가 됩니다.

2-3. 목차표

섹션들어갈 것
개요문제·분류·환경
분석관찰·가설·실패 포함
익스플로잇스크립트·실행 결과
교훈재사용 포인트

3. 예제

목차: 개요 → 분석 → 익스플로잇 → 교훈

3-2. 심화 예제: 30분 Write-up 루틴

# 풀이 중 실시간 메모 양식
# [시간] 시도한 것 → 결과 (성공/실패 한 줄)
# 10:00 strings 스캔 → URL 3개 발견
# 10:07 binwalk 시도 → 덧붙은 zip 없음
# 10:15 zsteg -a → LSB 평면에 문자열 발견!
# 마무리: 메모를 목차에 옮기고 스크립트·캡처 첨부
# 포인트: 명령은 복사-붙여넣기 가능하게 코드블록으로

4. 실습

  1. 풀이 1건을 Write-up으로 작성한다.
  2. 실시간 메모를 먼저 남긴다.
  3. 실패 1건을 포함시킨다.
  4. 스크립트·캡처를 첨부한다.
  5. 동료가 따라 할 수 있는지 검증받는다.

5. 퀴즈

  1. 재현 가능성의 의미는?
  2. 실패 기록이 유용한 이유는?
  3. 실시간 메모가 필요한 이유는?
  4. 캡처에 명령이 보여야 하는 이유는?
  5. 교훈 섹션의 용도는?
정답 보기
  1. 남이 같은 절차로 같은 결과에 닿는 것이다.
  2. 같은 함정 반복을 막고 가설 재료가 되기 때문이다.
  3. 끝나고 쓰면 과정이 증발하기 때문이다.
  4. 결과 조작 여부를 검증할 수 있기 때문이다.
  5. 다음 문제에 써먹을 패턴을 남기는 것이다.

5-2. 한눈에 보는 기록 흐름

sequenceDiagram participant S as 풀이자 participant M as 실시간 메모 participant W as Write-up S->>M: 시도·결과 기록 M->>M: 실패도 축적 S->>W: 목차로 정리 W-->>S: 검토·공개

읽는 법: 메모가 원재료, Write-up이 제품입니다. 원재료 없이 제품은 안 나옵니다.

6. 흔한 실수

  • 성공만 적고 실패를 지우는 경우. 자산이 반 토막 난다.
  • 스크립트 없이 캡처만 붙이는 경우
