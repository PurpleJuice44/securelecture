리버싱 Level 4 장(chapter)

crackme 패치 분석

분기 명령을 바꿔 인증을 우회하는 과정을 이해한다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • 문자열 비교 함수 위치 찾기
  • je(같으면 점프)→jne 로직 반전 개념
  • 패치는 실습 crackme에서만 수행

2. 핵심 개념

  • 문자열 비교 함수 위치 찾기
  • je(같으면 점프)→jne 로직 반전 개념
  • 패치는 실습 crackme에서만 수행

2-2. 동작 원리 심화: 인증 판정의 해부

crackme의 인증은 입력→비교→분기 3단계입니다. 비교 함수(strcmp 등)가 0(일치)을 돌려주면 성공 분기로 점프합니다. 패치는 이 분기 명령 1바이트를 뒤집어 로직을 반전시키는 것입니다.

flowchart TD I["입력 읽기
scanf·argv"] --> C["비교 호출
strcmp(input, answer)"] C --> R["반환값 eax"] R --> T{"je success?"} T -->|일치| S["성공 메시지"] T -->|불일치| F["실패 메시지"] P["패치
je→jne 1바이트"] --> T

읽는 법: 분기 명령이 인증의 목줄기입니다. 패치는 목줄기를 반대로 묶는 것으로, 실습용 crackme에서만 수행합니다.

2-3. 분기 명령표

명령조건패치 시 효과
je같으면 점프jne로 바꾸면 반전
jne다르면 점프je로 바꾸면 반전
jg / jl크다·작다 점프조건 뒤집기

3. 예제

je success  →  jne success  (개념 설명)

3-2. 심화 예제: 분기 찾기부터 패치까지(실습 crackme)

# 1) 성공·실패 문자열로 비교 함수 좁히기
strings crackme | grep -i -E "success|fail|wrong|correct"
# 2) 해당 문자열 참조 주소의 역참조 추적 (Ghidra XREF)
# 3) gdb에서 분기 주소 확인
gdb -q ./crackme
(gdb) b *main
(gdb) r test1234
(gdb) disas            # je/jne 주소 메모
# 4) 패치 (원본 백업 후 복사본에만!)
cp crackme crackme.bak
printf '\x75' | dd of=crackme.patched bs=1 seek=$((0x1234)) conv=notrunc
# 0x74(je)↔0x75(jne) 1바이트 교체 개념. 주소는 분석으로 확정할 것

4. 실습

  1. 실습 crackme의 정답 분기를 찾아 기록한다.
  2. 성공·실패 문자열의 상호참조로 비교 함수를 특정한다.
  3. 분기 명령의 옵코드(74·75)를 확인한다.
  4. 복사본에만 패치하고 원본 해시가 그대로인지 검증한다.
  5. 패치 전후 동작을 표로 비교한다.

5. 퀴즈

  1. je의 의미는?
  2. 패치 분석의 핵심 관찰 대상은?
  3. 원본이 아닌 복사본에 패치하는 이유는?
  4. 0x74와 0x75는 각각 무엇인가?
  5. 패치 후 반드시 하는 검증은?
정답 보기
  1. ZF=1(같음)일 때 점프한다.
  2. 비교 함수의 반환값을 소비하는 분기 명령이다.
  3. 원본 훼손 시 증거·학습 재료가 망가지므로, L0 원칙 그대로이다.
  4. je와 jne의 x86 옵코드이다.
  5. 틀린 입력으로 성공하고, 원본 해시가 변하지 않았는지 확인한다.

5-2. 한눈에 보는 패치 검증 흐름

sequenceDiagram participant A as 분석가 participant O as 원본 participant C as 복사본 A->>O: 해시 기록·봉인 A->>C: 분기 1바이트 교체 C-->>A: 오입력 성공 확인 A->>O: 해시 재대조 O-->>A: 불변 확인

읽는 법: 원본은最初부터 끝까지 건드리지 않습니다. 패치는 복사본의 실험일 뿐입니다.

6. 흔한 실수

  • 상용 소프트웨어에 패치를 적용하는 경우. 불법이며 이 강의 범위를 벗어난다.
  • 오프셋 계산 실수로 엉뚱한 바이트를 고치는 경우. 백업과 해시 검증이 안전망이다.
