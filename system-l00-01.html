시스템 Level 0 장(chapter)

리눅스 기초 명령

파일·프로세스·네트워크 기본 명령을 쓸 수 있다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • ls/cd/cp/mv/rm, chmod/chown
  • ps/top, systemctl
  • ip/ss/ping, man 활용

2. 핵심 개념

  • ls/cd/cp/mv/rm, chmod/chown
  • ps/top, systemctl
  • ip/ss/ping, man 활용

2-2. 동작 원리 심화: 셸과 커널 사이

명령어를 치면 셸이 해석→커널이 실행→결과 반환의 고리가 돕니다. 파일·프로세스·네트워크 명령은 각각 다른 커널 자원을 두드리므로, 출력 읽는 법부터 익히면 진단의 절반은 끝납니다.

flowchart TD U["사용자 입력
ls -l /"] --> S["셸 해석
인자·경로展开"] S --> K["시스템콜
open·getdents"] K --> F["파일시스템 조회"] F --> R["결과 반환
권한·크기·시각"] P["ps·ss"] --> K2["프로세스·소켓 조회"]

읽는 법: 모든 명령은 커널 조회의 포장지입니다. 출력의 각 열이 무엇을 뜻하는지 아는 것이 실력입니다.

2-3. 명령 3종 세트

영역명령볼 것
파일ls -l권한·소유자·크기·시각
프로세스ps aux소유자·CPU·명령
네트워크ss -tlnp대기 포트·프로세스

3. 예제

ls -l / man ls / ss -tlnp

3-2. 심화 예제: 읽기 루틴

# 1) 권한 읽기 (d rwx r-x r-x 해석)
ls -l /etc/passwd /etc/shadow
# 2) 수상 프로세스 찾기 (소유자·CPU·낯선 경로)
ps aux --sort=-%cpu | head
# 3) 열린 포트와 주인 확인
ss -tlnp
# 4) 모르면 그 자리에서 (man·--help)
man ls | head -20; ss --help | head -10

4. 실습

  1. 명령 5개를 직접 실행하고 결과를 기록한다.
  2. ls -l 출력 1줄을 7칸으로 나눠 해석한다.
  3. CPU 상위 프로세스 3개를 적고 정상 여부를 판단한다.
  4. 대기 포트 목록을 뽑아 불필요 서비스를 표시한다.
  5. 모르는 옵션 1개를 man으로 찾아 정리한다.

5. 퀴즈

  1. man의 용도는?
  2. ss로 보는 정보는?
  3. ls -l 첫 칸 drwxr-xr-x의 의미는?
  4. ps aux에서 수상 기준 2가지는?
  5. 포트와 프로세스를 함께 봐야 하는 이유는?
정답 보기
  1. 명령어 매뉴얼을 보는 것이다.
  2. 소켓 상태·포트·연결 프로세스이다.
  3. 디렉토리이며 소유자는 전부, 그룹·others는 읽기·실행만이다.
  4. 낯선 소유자·경로와 비정상 CPU 점유이다.
  5. 열린 포트가 어떤 프로그램 것인지 알아야 조치할 수 있기 때문이다.

5-2. 한눈에 보는 조회 흐름

sequenceDiagram participant A as 관리자 participant S as 셸 participant K as 커널 A->>S: 명령 입력 S->>K: 시스템콜 K-->>S: 자원 상태 S-->>A: 표 출력

읽는 법: 출력은 커널 상태의 스냅샷입니다. 주기적으로 찍어두면 변화 탐지의 기준선이 됩니다.

6. 흔한 실수

  • root로 습관적 작업하는 경우. 최소권한·sudo 원칙을 지킨다.
  • 출력을 읽지 않고 명령만 외우는 경우
