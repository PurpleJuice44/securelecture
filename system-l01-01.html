시스템 Level 1 장(chapter)

권한과 계정 관리

rwx와 최소권한 원칙을 적용한다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • r=4 w=2 x=1, chmod 750
  • 불필요 계정 잠금·삭제
  • sudoers 최소 권한

2. 핵심 개념

  • r=4 w=2 x=1, chmod 750
  • 불필요 계정 잠금·삭제
  • sudoers 최소 권한

2-2. 동작 원리 심화: rwx의 계산법

권한은 r=4·w=2·x=1의 합으로, 소유자·그룹·others 3칸에 각각 매깁니다. 750은 소유자 전부, 그룹 읽기·실행, others 차단입니다. 계정 관리의 핵심은 불필요한 권한·계정을 없애는 것입니다.

flowchart TD F["파일 접근 요청"] --> O{"소유자인가"} O -->|예| P1["소유자 권한 적용"] O -->|아니오| G{"같은 그룹인가"} G -->|예| P2["그룹 권한 적용"] G -->|아니오| P3["others 권한 적용"]

읽는 법: 위에서 아래로 먼저 맞는 칸 하나만 적용됩니다. others에 쓰기(w)가 있으면 누구나 고칠 수 있다는 뜻입니다.

2-3. 점검표

점검명령조치
월드쓰기 파일find / -perm -o+w권한 회수·이유 확인
불필요 계정awk -F: '$3>=1000' /etc/passwd잠금·삭제
sudo 권한visudo 점검필요 명령만 허용

3. 예제

chmod 750 app.sh / chown root:root app.sh

3-2. 심화 예제: 권한 점검 루틴

# 1) 월드쓰기 파일 사냥
find / -xdev -type f -perm -o+w 2>/dev/null | head
# 2) SUID·SGID 파일 목록 (다음 장 연계)
find / -xdev -type f -perm -4000 2>/dev/null | head
# 3) 로그인 가능 계정 정리
grep -v -E "nologin|false" /etc/passwd
# 4) sudo 권한 확인 (본인)
sudo -l

4. 실습

  1. 월드쓰기 파일을 찾아본다.
  2. 발견 파일마다 필요 여부를 판정한다.
  3. 불필요 계정 1개를 잠그는 절차를 적는다.
  4. chmod 600·750·644를 각각 해석한다.
  5. sudoers에 전권한(ALL)이 있으면 위험을 적는다.

5. 퀴즈

  1. chmod 600의 의미는?
  2. 최소권한 원칙이란?
  3. 월드쓰기가 위험한 이유는?
  4. 불필요 계정을 그냥 두면 생기는 일은?
  5. sudo ALL의 위험은?
정답 보기
  1. 소유자만 읽기·쓰기이다.
  2. 일에 필요한 최소 권한만 주는 것이다.
  3. 누구나 내용을 바꿔 백도어·변조가 가능하기 때문이다.
  4. 퇴사자·테스트 계정이 침입 통로가 된다.
  5. 해당 계정 탈취 즉시 root와 같아진다.

5-2. 한눈에 보는 권한 판정

sequenceDiagram participant U as 사용자 participant K as 커널 U->>K: 파일 쓰기 요청 K->>K: 소유·그룹·others 순 판정 K-->>U: 허용 또는 거부

읽는 법: 판정은 한 칸에서 끝납니다. others가 열려 있으면 앞 칸이 무의미해집니다.

6. 흔한 실수

  • 777로 때우는 경우. 동작은 하지만 보안은 무너진다.
  • 소유자를 root로만 바꾸고 권한은 그대로 두는 경우
