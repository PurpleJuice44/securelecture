시스템 Level 2 장(chapter)

방화벽과 서비스 관리

열린 문을 닫고 필요한 것만 허용한다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • ss -tlnp로 리스닝 확인
  • ufw allow/deny/deny 규칙
  • 불필요 서비스 비활성화

2. 핵심 개념

  • ss -tlnp로 리스닝 확인
  • ufw allow/deny/deny 규칙
  • 불필요 서비스 비활성화

2-2. 동작 원리 심화: 기본 거부·예외 허용

방화벽의 정석은 전부 막고 필요한 것만 여는 것입니다. 리스닝 포트 목록을 뽑고, 쓰는 것만 허용한 뒤, 나머지는 거부합니다. 불필요 서비스는 끄는 것이 가장 확실한 차단입니다.

flowchart TD L["ss -tlnp
리스닝 목록"] --> J["필요 여부 판정"] J --> U["불필요
서비스 중지·제거"] J --> N["필요
방화벽 허용"] N --> D["기본 거부
deny incoming"] D --> V["외부 스캔으로 검증"]

읽는 법: 목록→판정→차단의 순서입니다. 허용 규칙보다 기본 거부 정책이 먼저입니다.

2-3. 점검표

점검명령조치
리스닝 포트ss -tlnp불필요 종료
방화벽 상태ufw status verbose기본 거부+예외 허용
자동시작systemctl list-unit-files불필요 disable

3. 예제

ufw allow 22/tcp / ufw enable  (실습 VM)

3-2. 심화 예제: SSH만 남기기(실습 VM)

# 1) 현재 리스닝과 방화벽 상태 기록
ss -tlnp
sudo ufw status verbose
# 2) 기본 거부 후 SSH만 허용 (순서 엄수!)
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw enable
# 3) 불필요 서비스 중지 (예시)
sudo systemctl stop telnet.socket 2>/dev/null
sudo systemctl disable telnet.socket 2>/dev/null
# 4) 외부에서 포트 스캔으로 검증 (실습망)
nmap -F 실습호스트

4. 실습

  1. SSH만 허용하는 규칙을 작성한다.
  2. 규칙 적용 전후의 리스닝 목록을 비교한다.
  3. 불필요 서비스 1개를 중지·비활성화한다.
  4. 외부 스캔으로 열린 포트를 검증한다.
  5. 되돌리기 절차(ufw disable·규칙 삭제)를 적는다.

5. 퀴즈

  1. 리스닝 확인 명령은?
  2. 기본 정책 설정 순서는?
  3. 허용 전 기본 거부를 먼저 하는 이유는?
  4. 서비스 중지와 방화벽 차단의 차이는?
  5. ufw enable 전 확인해야 할 것은?
정답 보기
  1. ss -tlnp이다.
  2. 기본 거부→예외 허용→활성화 순서이다.
  3. 순서가 뒤바뀌면 자신을 차단해 접속이 끊기기 때문이다.
  4. 중지는 공격 표면 제거, 차단은 접근 차단이다. 둘 다 한다.
  5. SSH 허용 규칙 존재 여부이다. 없으면 원격 접속이 끊긴다.

5-2. 한눈에 보는 차단 순서

sequenceDiagram participant A as 관리자 participant F as 방화벽 participant N as 외부 A->>F: 기본 거부 설정 A->>F: SSH 허용 추가 A->>F: 활성화 N->>F: 포트 스캔 F-->>N: SSH만 응답

읽는 법: 거부→허용→활성화→검증의 순서입니다. 활성화 전 SSH 규칙 확인이 생명줄입니다.

6. 흔한 실수

  • 원격에서 SSH 허용 없이 ufw enable해 접속이 끊기는 경우
  • 방화벽만 믿고 서비스 자체를 끄지 않는 경우
