포너블 Level 2 장(chapter)

RET 덮기와 rip 장악

오프셋을 찾아 복귀주소를 덮는다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • 패턴 입력으로 오프셋 계산
  • RET 위치에 원하는 주소 삽입
  • 코어덤프·gdb로 rip 확인

2. 핵심 개념

  • 패턴 입력으로 오프셋 계산
  • RET 위치에 원하는 주소 삽입
  • 코어덤프·gdb로 rip 확인

2-2. 동작 원리 심화: 오프셋에서 장악까지

오프셋은 입력 시작부터 RET까지의 거리입니다. 패턴 입력으로 crash를 내고 rip에 박힌 값을 역산하면 거리가 확정되고, 그 위치에 원하는 주소를 심으면 흐름이 넘어옵니다.

flowchart TD P["패턴 입력
cyclic 200자"] --> C["crash
rip 확인"] C --> O["오프셋 계산
pattern_offset"] O --> V["검증 입력
A×오프셋 + BBBB"] V --> R{"rip=0x42424242?"} R -->|예| W["장악 확정
주소 삽입 단계로"] R -->|아니오| P

읽는 법: BBBB가 rip에 그대로 박히면 거리 확정입니다. 코어덤프·gdb 둘 중 편한 것으로 확인합니다.

2-3. 확인 방법표

방법명령장점
코어덤프dmesg·core + gdb재현 없이 사후 분석
실시간 gdbr < pattern즉시 rip 확인
pwntoolscyclic_find()자동 계산

3. 예제

pattern_create → crash → pattern_offset (개념)

3-2. 심화 예제: 오프셋 확정 루틴(실습 VM)

# 1) 패턴 생성·전달 후 crash
python3 -c "from pwn import *; print(cyclic(200))" > pay
./vuln < pay   # Segmentation fault
# 2) rip 값으로 오프셋 역산 (gdb)
gdb -q ./vuln core
(gdb) i r rip        # 예: 0x6161616c
(gdb) quit
python3 -c "from pwn import *; print(cyclic_find(0x6161616c))"
# 3) 검증: A×오프셋 + BBBB → rip=0x42424242 확인

4. 실습

  1. 실습 바이너리의 오프셋을 구한다.
  2. BBBB 검증 입력으로 rip 장악을 증명한다.
  3. 코어덤프 방식과 실시간 gdb 방식을 둘 다 해본다.
  4. 오프셋±4 오차가 생기는 경우를 기록한다.
  5. 과정을 표(입력·rip·판정)로 정리한다.

5. 퀴즈

  1. 오프셋이란?
  2. rip 장악의 의미는?
  3. cyclic 패턴을 쓰는 이유는?
  4. BBBB 검증의 목적은?
  5. 코어덤프가 안 생기면 확인할 것은?
정답 보기
  1. 입력 시작부터 RET까지의 바이트 거리이다.
  2. ret 실행 시 점프할 주소를 공격자가 정하게 되는 것이다.
  3. 덮인 값으로 거리를 역산할 수 있기 때문이다.
  4. 계산된 오프셋이 정확한지 증명하기 위해서이다.
  5. ulimit -c 코어 크기와 디렉토리 쓰기 권한이다.

5-2. 한눈에 보는 장악 증명

sequenceDiagram participant A as 공격자 participant P as vuln A->>P: cyclic 입력 P-->>A: crash·rip 값 A->>A: 오프셋 계산 A->>P: A×N + BBBB P-->>A: rip=BBBB 장악 증명

읽는 법: BBBB가 찍히는 순간 이후 모든 공격(셸코드·ROP)의 발판이 마련됩니다.

6. 흔한 실수

  • 환경 변수·인자 길이가 달라 오프셋이 흔들리는 경우. 동일 조건에서 잰다.
  • SFP까지만 덮고 RET 한 바이트가 모자라 실패하는 경우
