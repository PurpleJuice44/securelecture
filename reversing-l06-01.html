리버싱 Level 6 장(chapter)

UPX 패킹 분석

패킹 개념과 언패킹 흐름을 이해한다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • 패킹=압축+실행시 복원, OEP 개념
  • upx -d 로 실습파일 언패킹
  • 패킹된 파일의 strings 특징(적음)

2. 핵심 개념

  • 패킹=압축+실행시 복원, OEP 개념
  • upx -d 로 실습파일 언패킹
  • 패킹된 파일의 strings 특징(적음)

2-2. 동작 원리 심화: 포장지를 벗기는 과정

패커는 원본 코드를 압축해 복원 스텁과 함께 묶습니다. 실행되면 스텁이 메모리에 원본을 풀고 OEP(원래 진입점)로 점프합니다. 분석은 OEP를 찾아 메모리 덤프를 뜨는 것이 핵심입니다.

flowchart TD O["원본 실행파일"] --> P["패킹
압축+스텁 부착"] P --> X["실행 시작
스텁 진입점"] X --> U["메모리 복원
원본 압축 해제"] U --> J["OEP 점프
원래 코드 시작"] J --> R["정상 실행"] A["분석가"] --> D["OEP에서 덤프
언패킹"]

읽는 법: 실행 흐름은 스텁→복원→OEP 순입니다. 분석가는 OEP 순간을 낚아채 덤프합니다.

2-3. 패킹 탐지 단서

단서정상패킹 의심
strings 개수수백 개수십 개 이하
섹션 이름.text·.dataUPX0·UPX1 등
엔트로피5~67.5 이상
임포트다양함LoadLibrary·GetProcAddress 위주

3. 예제

upx -d packed.exe -o unpacked.exe

3-2. 심화 예제: 패킹 전후 비교(실습 파일)

# 1) 패킹 전 기준선
file original && strings original | wc -l
readelf -S original | head -15
# 2) 패킹 (실습 파일에만!)
upx original -o packed
# 3) 패킹 후 비교
file packed && strings packed | wc -l
readelf -S packed | grep -i upx
# 4) 언패킹 후 동등성 확인
upx -d packed -o unpacked
cmp <(strings original | sort) <(strings unpacked | sort) && echo "복원 일치"

4. 실습

  1. 패킹 전/후 strings 개수를 비교한다.
  2. 섹션 이름과 엔트로피 변화를 기록한다.
  3. upx -d로 복원하고 문자열이 돌아오는지 확인한다.
  4. UPX 외 패커 식별법(PEiD·DIEC 개념)을 조사한다.
  5. 수동 언패킹 개념(OEP 브레이크→덤프)을 순서도로 그린다.

5. 퀴즈

  1. OEP란?
  2. 패킹 탐지 단서는?
  3. 스텁의 역할은?
  4. 언패킹 후 반드시 하는 검증은?
  5. strings가 비었다고 무조건 패킹인가? 다른 경우는?
정답 보기
  1. Original Entry Point. 패킹 전 원본 코드의 시작 주소이다.
  2. strings 급감, UPX 섹션명, 높은 엔트로피, 적은 임포트이다.
  3. 실행 시 원본을 메모리에 복원하고 OEP로 점프하는 것이다.
  4. 원본과 동등한지(문자열·동작) 대조하는 것이다.
  5. 아니다. 스트립·난독화도 가능하다. 여러 단서를 종합한다.

5-2. 한눈에 보는 수동 언패킹

sequenceDiagram participant A as 분석가 participant D as 디버거 participant M as 메모리 A->>D: 스텁 진입점에 정지 D->>M: 단계 실행하며 복원 관찰 M-->>D: OEP 점프 순간 포착 D->>D: 프로세스 덤프 D-->>A: 언패킹 파일 확보

읽는 법: OEP로 점프하는 바로 그 순간이 덤프 타이밍입니다. 점프 후 한 칸이 골든타임입니다.

6. 흔한 실수

  • 패킹=악성코드로 단정하는 경우. 정상 소프트웨어도 용량·보호 목적으로 패킹한다.
  • 언패킹 파일을 원본처럼 신뢰하는 경우. 덤프는 복원본이라 IAT 재구축 등이 필요할 수 있다.
