커널 익스플로잇 개요

커널 권한상승의 개념과 방어기법을 이해한다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • ret2usr, SMEP/SMAP 개념
  • 커널=전체 권한, 실패 시 크래시
  • 실습은 전용 VM에서만

2. 핵심 개념

  • ret2usr, SMEP/SMAP 개념
  • 커널=전체 권한, 실패 시 크래시
  • 실습은 전용 VM에서만

2-2. 동작 원리 심화: 경계의 양쪽

유저 프로세스가 커널 함수를 부르면 시스템콜 문을 통과합니다. 커널 익스플로잇은 이 문의 검사 허점을 노려 권한을 올립니다. 방어기법(SMEP·SMAP·KASLR)은 커널이 유저 영역을 믿지 않게 막습니다.

flowchart TD U["유저 프로세스
낮은 권한"] --> S["시스템콜
검사 지점"] S --> K["커널 실행
전체 권한"] K --> R["결과 반환"] V["취약점
검사 우회"] --> E["권한 상승
root 획득"] D["SMEP·SMAP·KASLR"] --> B["유저 코드·주소 차단"]

읽는 법: 문(시스템콜)이 유일한 통로입니다. 공격은 문을 속이고, 방어는 문을 좁힙니다.

2-3. 방어기법표

기법막는 것
SMEP커널에서 유저코드 실행
SMAP커널에서 유저메모리 접근
KASLR커널 주소 예측
cred 구조 보호권한 구조체 변조

4. 실습

  1. 방어기법 3종을 정리한다.
  2. 실습 VM의 방어 옵션을 읽어 표로 만든다.
  3. 유명 CVE 1개의 트리거 조건을 요약한다.
  4. ret2usr가 SMEP에서 막히는 이유를 설명한다.
  5. 커널 분석 학습 로드맵을 한 페이지로 그린다.

5. 퀴즈

  1. SMEP의 역할은?
  2. 커널 공격이 위험한 이유는?
  3. SMAP과 SMEP의 차이는?
  4. 커널 크래시가 치명적인 이유는?
  5. 커널 실습이 전용 VM을 요구하는 이유는?
정답 보기
  1. 커널 모드에서 유저 영역 코드 실행을 차단하는 것이다.
  2. 성공하면 전체 권한, 실패하면 시스템 전체가 멈추기 때문이다.
  3. SMEP는 실행 차단, SMAP은 접근 차단이다.
  4. 전체 시스템이 멈춰 증거·작업이 함께 날아가기 때문이다.
  5. 실패=크래시라 격리·스냅샷 없이는 복구가 불가하기 때문이다.

5-2. 한눈에 보는 공격·방어

sequenceDiagram participant A as 공격자 participant S as 시스템콜 participant K as 커널 A->>S: 검사 우회 입력 S->>K: 권한 상승 시도 K->>K: SMEP·SMAP 검사 K-->>A: 차단 또는 상승

읽는 법: 이 장은 개요 수준입니다. 실전은 별도 커널 과정과 전용 실습장에서 이어갑니다.

6. 흔한 실수

  • 유저 익스플로잇 감각으로 커널에 덤비는 경우. 실패 비용이 다르다.
  • 호스트·공유망에서 커널 PoC를 돌리는 경우. 전용 격리 VM이 원칙이다.
