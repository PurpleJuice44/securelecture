웹 Level 0 장(chapter)

웹 동작원리

브라우저가 서버와 대화하는 전체 흐름을 이해한다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • 클라이언트(브라우저)와 서버의 역할 구분
  • URL 입력부터 화면 표시까지: DNS→TCP→HTTP→렌더링
  • 정적 페이지와 동적 페이지의 차이

2. 핵심 개념

  • 클라이언트(브라우저)와 서버의 역할 구분
  • URL 입력부터 화면 표시까지: DNS→TCP→HTTP→렌더링
  • 정적 페이지와 동적 페이지의 차이

2-2. 동작 원리 심화: URL 한 줄의 여행

주소창에 URL을 입력하고 엔터를 치면, 화면이 나타나기까지 5단계가 순식간에 일어납니다. 해킹은 이 중 한 단계를 가로채거나 속이는 것부터 시작합니다.

flowchart TD U["URL 입력
https://shop.example/item?id=7"] --> D["DNS 조회
도메인→IP 변환"] D --> T["TCP+TLS 연결
3-way 핸드셰이크·인증서 검증"] T --> H["HTTP 요청
GET /item?id=7"] H --> S["서버 처리
라우팅·DB 조회·HTML 생성"] S --> R["HTTP 응답
200 OK + HTML"] R --> B["브라우저 렌더링
파싱·CSS·JS 실행"]

읽는 법: 위에서 아래로 시간 순서입니다. 각 단계마다 공격 지점이 있습니다. DNS 스푸핑은 D, 패킷 도청은 T, XSS는 B 단계의 문제입니다.

2-3. 정적 vs 동적 페이지

구분정적 페이지동적 페이지
응답 생성미리 만든 HTML 그대로 전송요청마다 서버가 HTML 조립
공격 표면좁음(서버 설정·업로드 위주)넓음(SQLi·XSS·인증 전부 가능)
예시회사 소개 페이지쇼핑몰·게시판·로그인

3. 예제

브라우저에 URL 입력 → DNS 조회 → TCP 연결 → HTTP 요청 → HTML 응답 → 렌더링

3-2. 심화 예제: curl로 맨눈에 보기

# DNS 결과 확인
nslookup shop.example
# TCP 연결 시간 측정 (TLS 포함)
curl -o /dev/null -s -w "연결:%{time_connect}초 TLS:%{time_appconnect}초 전체:%{time_total}초\n" https://shop.example/
# HTTP 요청·응답 헤더 들여다보기
curl -sI https://shop.example/item?id=7

4. 실습

  1. 개발자도구 Network 탭에서 새로고침 후 요청 1개를 클릭해 Headers를 읽어본다.
  2. 해당 요청의 Remote Address가 DNS 결과와 같은지 대조한다.
  3. curl -sI로 같은 URL의 상태코드·Content-Type을 확인한다.
  4. 정적 파일(css·이미지)과 동적 응답(XHR)을 구분해본다.
  5. 위 5단계를 자신의 말로 한 줄씩 정리한다.

5. 퀴즈

  1. DNS의 역할은?
  2. 정적/동적 페이지의 차이는?
  3. TLS가 보호하는 구간은 어디부터 어디까지인가?
  4. 브라우저 렌더링 단계에서 실행되는 것 2가지는?
  5. 동적 페이지가 공격 표면이 넓은 이유는?
정답 보기
  1. 사람이 읽는 도메인을 컴퓨터가 쓰는 IP로 바꿔주는 전화번호부이다.
  2. 정적은 미리 만든 HTML을 그대로 주고, 동적은 요청마다 서버가 조립해서 준다.
  3. 브라우저와 서버 사이 전송 구간이다. 서버 내부 처리나 브라우저 저장소는 보호하지 않는다.
  4. HTML 파싱·CSS 적용·JavaScript 실행이다.
  5. 사용자 입력이 DB·세션·파일 등 내부 자원에 닿는 지점이 많기 때문이다.

5-2. 한눈에 보는 요청 흐름

sequenceDiagram participant U as 사용자 participant B as 브라우저 participant D as DNS participant S as 웹 서버 U->>B: URL 입력 B->>D: 도메인 질의 D-->>B: IP 응답 B->>S: TCP+TLS 연결 B->>S: HTTP 요청 S-->>B: HTML 응답 B-->>U: 화면 표시

읽는 법: 왼쪽이 사용자, 오른쪽이 서버입니다. 화살표마다 가로챌 수 있는 공격이 존재한다는 점이 이 분야 전체의 전제입니다.

6. 흔한 실수

  • URL=웹사이트 전체로 오해하는 경우. URL은 그 안의 자원 하나를 가리키는 주소이다.
  • TLS를 쓰면 서버까지 전부 안전한 것으로 착각하는 경우
