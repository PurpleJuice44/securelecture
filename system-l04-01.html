시스템 Level 4 장(chapter)

크론 권한상승 점검

예약작업의 쓰기권한 문제를 점검한다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • /etc/crontab·cron.d 확인
  • 스크립트 파일 쓰기권한 검사
  • root 실행 스크립트 변조 시나리오

2. 핵심 개념

  • /etc/crontab·cron.d 확인
  • 스크립트 파일 쓰기권한 검사
  • root 실행 스크립트 변조 시나리오

2-2. 동작 원리 심화: root의 알람시계

크론은 정해진 시간에 정해진 명령을 실행합니다. root 크론이 실행하는 스크립트를 일반 사용자가 고칠 수 있으면, 다음 실행 때 root 권한으로 공격자 코드가 돕니다. 점검 포인트는 스케줄→스크립트→쓰기권한의 사슬입니다.

flowchart TD C["크론 설정 확인
crontab·cron.d"] --> S["실행 스크립트 특정"] S --> W{"누가 쓸 수 있나"} W -->|root만| OK["양호"] W -->|타인 가능| V["변조 가능
고위험"] V --> F["권한 회수·소유자 정리"]

읽는 법: 누가 실행하나가 아니라 누가 고칠 수 있나가 핵심입니다. 실행자는 root, 수정자는 나면 뚫린 것입니다.

2-3. 점검 위치표

위치확인
/etc/crontab시스템 스케줄
/etc/cron.d/추가 스케줄
/var/spool/cron/사용자 크론
스크립트 본체쓰기권한·소유자

3. 예제

cat /etc/crontab / ls -l /etc/cron*

3-2. 심화 예제: 사슬 추적 루틴

# 1) 스케줄 전체 수집
cat /etc/crontab
ls -l /etc/cron.d/ /etc/cron.daily/
crontab -l 2>/dev/null
# 2) root 실행 스크립트의 쓰기권한 검사
ls -l /usr/local/bin/cleanup.sh   # 예시 경로
# 3) 디렉토리 쓰기권한까지 확인 (교체 공격)
ls -ld /usr/local/bin/
# 4) 조치: 소유자 정리·쓰기 제거 (실습 VM)
# chown root:root script.sh && chmod 755 script.sh

4. 실습

  1. 쓰기 가능한 크론 스크립트를 찾는다.
  2. 스케줄→스크립트→권한 사슬을 그림으로 그린다.
  3. 디렉토리 쓰기권한까지 검사한다.
  4. 조치 후 재점검 결과를 기록한다.
  5. 점검 주기(주·월)를 정해 문서화한다.

5. 퀴즈

  1. 크론 점검 항목은?
  2. 대응법은?
  3. 스크립트뿐 아니라 디렉토리도 보는 이유는?
  4. 실행 주기가 짧을수록 위험한 이유는?
  5. 크론 로그를 봐야 하는 이유는?
정답 보기
  1. 스케줄 목록·실행 주체·스크립트 쓰기권한이다.
  2. 소유자 정리·쓰기 제거·불필요 스케줄 삭제이다.
  3. 디렉토리에 쓸 수 있으면 스크립트를 교체할 수 있기 때문이다.
  4. 변조부터 실행까지 시간이 짧아 대응이 어렵기 때문이다.
  5. 실패·변경 흔적을 조기 발견하기 위해서이다.

5-2. 한눈에 보는 점검 사슬

sequenceDiagram participant A as 점검자 participant C as 크론 설정 participant F as 스크립트 A->>C: 스케줄 수집 C-->>A: 실행 주체·주기 A->>F: 쓰기권한 검사 F-->>A: 취약 판정·조치

읽는 법: 설정→본체→권한의 3단 추적입니다. 한 곳만 보면 사슬이 끊깁니다.

6. 흔한 실수

  • 스크립트만 보고 디렉토리 권한을 놓치는 경우
  • 점검 후 조치 기록을 안 남겨 재발하는 경우
