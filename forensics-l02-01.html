포렌식 Level 2 장(chapter)

메타데이터 분석

파일 속 숨은 정보를 추출한다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • exiftool로 촬영정보·문서작성자 확인
  • 삭제된 정보도 단서가 됨
  • 개인정보 포함 시 취급주의

2. 핵심 개념

  • exiftool로 촬영정보·문서작성자 확인
  • 삭제된 정보도 단서가 됨
  • 개인정보 포함 시 취급주의

2-2. 동작 원리 심화: 메타데이터가 남는 위치

메타데이터는 파일 바깥이 아니라 안에 저장됩니다. 사진을 찍으면 카메라가 EXIF 영역에 시각·GPS·기종을 쓰고, 문서를 저장하면 오피스 프로그램이 작성자·편집 시간을 기록합니다. 삭제해도 흔적이 남는 이유는, 많은 형식이 값을 지워도 영역을 0으로 덮지 않기 때문입니다.

flowchart TD F["파일 입수"] --> T{"형식 판별"} T -->|이미지| EXIF["EXIF·XMP 추출
exiftool"] T -->|문서| DOC["작성자·편집이력 추출
oletools·exiftool"] T -->|실행파일| PE["PE 타임스탬프·버전 추출"] EXIF --> DEL{"삭제·위조 흔적?"} DOC --> DEL PE --> DEL DEL -->|예| CMP["원본 대조·타임라인 편입"] DEL -->|아니오| REP["정상 기록·보고"]

읽는 법: 형식에 맞는 도구를 골라 추출한 뒤, 값이 비어 있거나 서로 모순되면(촬영 시각 vs 파일 생성 시각) 위조·삭제를 의심합니다.

2-3. 개인정보 취급 주의

  • GPS 좌표·기기 시리얼·작성자 실명은 개인정보이므로 보고서에 원본 그대로 싣지 말고 마스킹한다.
  • 분석용 사본과 보고서 유출 경로를 분리하고, 불필요한 메타데이터는 배포 전에 제거한다.

3. 예제

exiftool photo.jpg | head -20

3-2. 심화 예제

# 1) 전체 태그 + GPS만 따로
exiftool photo.jpg
exiftool -GPSPosition -CreateDate photo.jpg
# 2) 문서 작성자·편집 이력
exiftool report.docx | grep -i -E "author|create|modify"
# 3) 메타데이터 제거본 만들기 (배포용)
exiftool -all= -o clean.jpg photo.jpg
diff <(exiftool photo.jpg) <(exiftool clean.jpg) | head

4. 실습

  1. 스마트폰 사진의 CreateDate와 파일 생성 시각을 비교한다.
  2. GPS 태그 유무를 확인하고, 있으면 지도상 위치와 촬영 장소 설명이 맞는지 본다.
  3. docx 파일의 작성자·최종 수정자를 추출한다.
  4. -all=로 정제본을 만들고 전후 태그 수를 비교한다.
  5. 위조 의심 포인트 1개를 골라 근거와 함께 기록한다.

5. 퀴즈

  1. 메타데이터의 예 3가지는?
  2. 왜 단서가 되는가?
  3. 삭제된 메타데이터가 단서가 되는 이유는?
  4. 보고서에 GPS 원본 좌표를 그대로 싣지 말아야 하는 이유는?
  5. 촬영 시각과 파일 생성 시각이 다르면 무엇을 의심하는가?
정답 보기
  1. 촬영 시각·GPS, 문서 작성자·편집 이력, PE 타임스탬프 등이다.
  2. 사용자가 의식하지 못한 채 기록되는 행위기반 정보라 위조가 어렵기 때문이다.
  3. 삭제해도 영역이 0으로 덮이지 않거나, 썸네일·미리보기 등 다른 위치에 복사본이 남기 때문이다.
  4. 실거주지 등 개인정보가 노출되어 2차 피해가 발생하기 때문이다. 마스킹이 원칙이다.
  5. 메타데이터 위조 또는 파일 재저장·재인코딩을 의심하고 원본 대조로 들어간다.

6. 흔한 실수

  • 썸네일 속 EXIF는 보지 않고 원본만 확인해 위조를 놓치는 경우
  • 타임존을 고려하지 않고 시각을 해석해 타임라인이 어긋나는 경우
