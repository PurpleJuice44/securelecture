웹 Level 5 장(chapter)

XSS (크로스사이트 스크립팅)

스크립트 삽입 공격의 3종류와 대응을 배운다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • Stored / Reflected / DOM-based 차이
  • 대표 페이로드:
  • 대응: 출력 인코딩, CSP, HttpOnly 쿠키

2. 핵심 개념

  • Stored / Reflected / DOM-based 차이
  • 대표 페이로드:
  • 대응: 출력 인코딩, CSP, HttpOnly 쿠키

2-2. 동작 원리 심화: 3종 XSS 비교

세 종류의 차이는 악성 스크립트가 어디에 머무는가입니다. Stored는 서버 DB에 저장되어 피해자마다 실행되고, Reflected는 URL에 실려 일회성으로 반사되며, DOM은 서버를 거치지 않고 브라우저 안에서 완성됩니다.

flowchart TD A["공격자 페이로드"] --> S{"어디에 머무는가"} S -->|DB 저장| ST["Stored
게시글·댓글"] S -->|URL 반사| RF["Reflected
검색어·에러page"] S -->|브라우저 내| DM["DOM-based
location.hash"] ST --> V["피해자 접속 시 실행"] RF --> V2["링크 클릭 시 실행"] DM --> V3["스크립트 싱크 도달 시 실행"] V --> T["쿠키 탈취·권한 도용"]

읽는 법: 저장형이 가장 파급력이 크고, DOM형이 탐지하기 가장 어렵습니다. 대응은 세 종류 모두 출력 인코딩이 기본입니다.

2-3. 대응 3종

대응막는 것한계
출력 인코딩HTML·JS 문맥 삽입문맥별(HTML/JS/URL) 구분 적용 필요
CSP인라인 스크립트 실행정책이 느슨하면 우회 가능
HttpOnly 쿠키쿠키 탈취XSS 자체를 막지는 못함

3. 예제

<script>alert(document.cookie)</script>  (실습 환경에서만)

3-2. 심화 예제: 유형별 페이로드와 확인(실습 게시판)

<!-- Reflected 확인용: 검색창 입력 후 URL·응답에 그대로 반사되는가 -->
<img src=x onerror=alert(1)>
<!-- Stored 확인용: 게시글 저장 후 다른 계정으로 접속해도 실행되는가 -->
<svg onload=alert(2)>
<!-- DOM 확인용: 해시값이 innerHTML로 들어가는가 -->
#visible... → location.hash 흐름 추적
<!-- 대응 확인: 인코딩 적용 후 < 가 &lt; 로 보이는가 -->

4. 실습

  1. 실습 게시판에 페이로드 입력 → 동작 관찰 → 대응 코드 작성.
  2. Stored와 Reflected를 각각 재현하고 차이를 표로 정리한다.
  3. 개발자도구 Elements에서 삽입 지점의 문맥(태그 안·속성 안·스크립트 안)을 확인한다.
  4. 출력 인코딩 적용 후 페이로드가 무력화되는지 검증한다.
  5. CSP 헤더를 추가하고 인라인 스크립트가 차단되는지 확인한다.

5. 퀴즈

  1. Stored와 Reflected의 차이는?
  2. CSP가 막아주는 것은?
  3. DOM XSS가 서버 로그에 안 남을 수 있는 이유는?
  4. HttpOnly가 XSS를 막지 못하는데도 쓰는 이유는?
  5. 속성 값 안(<input value="...">)에 삽입될 때 필요한 탈출 문자는?
정답 보기
  1. Stored는 서버에 저장되어 다수에게, Reflected는 URL 반사로 클릭한 당사자에게 실행된다.
  2. 허용 목록 밖 스크립트의 실행(특히 인라인)을 차단한다.
  3. 해시(#) 이후 값은 서버로 전송되지 않고 브라우저 안에서만 처리되기 때문이다.
  4. XSS가 터져도 세션 쿠키 탈취라는 최악 경로를 차단해 피해를 줄이기 때문이다.
  5. 큰따옴표 탈출("><svg...)이다. 문맥을 먼저 파악해야 한다.

5-2. 한눈에 보는 공격·대응 매핑

sequenceDiagram participant A as 공격자 participant S as 서버 participant V as 피해자 A->>S: 페이로드 저장·반사 V->>S: 페이지 요청 S-->>V: 스크립트 포함 응답 V->>V: 브라우저 실행 V->>A: 세션·키스트로크 유출

읽는 법: 서버가 스크립트를 그대로 돌려주는 지점이 취약점, 브라우저가 실행하는 지점이 피해 발생점입니다. 인코딩은 돌려주기 전에 적용합니다.

6. 흔한 실수

  • <script> 문자열만 차단하는 경우. 이벤트 핸들러·svg 등 우회 경로가 무수하다.
  • 입력 필터만 하고 출력 인코딩을 빼먹는 경우. 방어는 출력 지점이 본진이다.
