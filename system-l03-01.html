시스템 Level 3 장(chapter)

SUID 권한상승 점검

SUID 바이너리의 위험을 점검한다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • find / -perm -u=s 로 목록화
  • GTFO bins 개념(알려진 악용법)
  • 소유자·필요성 검토 후 권한 제거

2. 핵심 개념

  • find / -perm -u=s 로 목록화
  • GTFO bins 개념(알려진 악용법)
  • 소유자·필요성 검토 후 권한 제거

2-2. 동작 원리 심화: 남의 권한 빌려 쓰기

SUID 비트가 붙은 파일은 실행한 사람이 아니라 파일 주인의 권한으로 동작합니다. 주인이 root인데 그 프로그램에 셸 탈출·파일 읽기 기능이 있으면, 일반 사용자가 root 권한을 빌려 쓰는 셈이 됩니다.

flowchart TD F["SUID 파일 발견
-rwsr-xr-x"] --> O{"주인이 root인가"} O -->|아니오| L["낮은 위험
기록만"] O -->|예| G["GTFO bins 대조
알려진 악용법"] G --> N{"필요한가"} N -->|예| K["유지·모니터링"] N -->|아니오| R["SUID 제거
chmod u-s"]

읽는 법: 목록화→소유자 확인→악용법 대조→필요성 판정의 순서입니다. 모르면 지우는 것이 아니라 판단 근거를 남기고 지웁니다.

2-3. 점검표

점검명령판단
SUID 목록find / -perm -u=s표준 외 낯선 파일 주목
소유자ls -lroot 소유가 고위험
악용법GTFOBins 대조셸 탈출 가능 여부

3. 예제

find / -perm -u=s -type f 2>/dev/null

3-2. 심화 예제: 점검 루틴

# 1) SUID 전체 목록 (에러 숨김)
find / -xdev -type f -perm -u=s 2>/dev/null | sort > suid.txt
wc -l suid.txt
# 2) 낯선 파일 골라내기 (표준: su·sudo·passwd·mount 등)
cat suid.txt
# 3) 의심 파일의 기능 확인 (도움말·문자열)
strings /의심경로 | grep -i -E "sh|system|exec" | head
# 4) 불필요 확정 시 권한 제거 (실습 VM, 근거 기록 후)
# chmod u-s /의심경로

4. 실습

  1. SUID 3개의 필요성을 평가한다.
  2. 표준 SUID와 낯선 SUID를 구분해 표로 만든다.
  3. 의심 파일의 문자열에서 위험 기능을 찾는다.
  4. 제거·유지 판정과 근거를 각각 한 줄로 적는다.
  5. GTFOBins에서 해당 바이너리 항목을 읽는다.

5. 퀴즈

  1. SUID란?
  2. 제거 판단 기준은?
  3. root 소유 SUID가 위험한 이유는?
  4. 무작정 지우면 안 되는 이유는?
  5. GTFOBins의 용도는?
정답 보기
  1. 실행 시 파일 주인 권한으로 동작하는 특수 비트이다.
  2. 필요성·대체수단·악용 가능성이다.
  3. 악용 시 root 권한을 그대로 빌려 쓰기 때문이다.
  4. 시스템 필수 기능(su·sudo 등)이 멈추기 때문이다.
  5. 바이너리별 알려진 악용법을 정리한 참고 자료이다.

5-2. 한눈에 보는 점검 흐름

sequenceDiagram participant A as 점검자 participant S as 시스템 A->>S: SUID 목록 수집 S-->>A: 전체 목록 A->>A: 소유자·필요성 판정 A->>S: 불필요 비트 제거 S-->>A: 재점검·기록

읽는 법: 수집→판정→조치→기록의 고리입니다. 정기 점검으로 새로 생긴 SUID를 잡습니다.

6. 흔한 실수

  • 제거 근거를 남기지 않아 다음 점검 때 같은 논쟁을 반복하는 경우
