시스템 Level 8 장(chapter)

서버 하드닝 체크리스트

배포 전 굳히기 항목을 적용한다.

⚠️ 실습은 본인 소유 VM·실습용 사이트(허가된 환경)에서만 수행하세요.

1. 학습 목표

  • SSH 키인증·root 차단
  • 불필요 포트 차단, 자동업데이트
  • 백업·로그 보관 정책

2. 핵심 개념

  • SSH 키인증·root 차단
  • 불필요 포트 차단, 자동업데이트
  • 백업·로그 보관 정책

2-2. 동작 원리 심화: 굳히기의 4기둥

하드닝은 접근 통제·표면 축소·최신 유지·복구 준비의 4기둥입니다. SSH를 키인증으로 바꾸고, 포트·서비스를 줄이고, 자동업데이트를 켜고, 백업·로그를 남깁니다.

flowchart TD A["SSH 강화
키인증·root 차단"] --> P["포트·서비스 축소
방화벽·disable"] P --> U["자동업데이트
무인 패치"] U --> B["백업·로그
복구·추적"]

읽는 법: 위에서 아래로가 적용 순서입니다. 접근 통제부터 해야 나머지가 의미를 가집니다.

2-3. 체크리스트 10항목

#항목확인
1SSH 키인증PasswordAuthentication no
2root 직접 로그인 차단PermitRootLogin no
3방화벽 기본 거부ufw default deny
4불필요 서비스 중지systemctl list
5자동업데이트unattended-upgrades
6월드쓰기 제거find -perm -o+w
7SUID 정리L3 연계
8계정 정리L1 연계
9백업복원 시험 포함
10로그 보관원격 전송

3. 예제

체크리스트 10항목 표로 점검

3-2. 심화 예제: SSH 굳히기(실습 VM)

# 1) 키 생성·등록 (관리자 PC)
ssh-keygen -t ed25519
ssh-copy-id user@실습호스트
# 2) 설정 변경 전 백업!
sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak
# 3) 강화 적용
# PasswordAuthentication no
# PermitRootLogin no
sudo systemctl restart sshd
# 4) 새 세션에서 키 로그인 확인 후 기존 세션 종료

4. 실습

  1. 실습 VM에 5개 항목을 적용한다.
  2. 적용 전후를 체크리스트에 표시한다.
  3. SSH 키 로그인을 검증한다.
  4. 백업 복원 시험을 1회 수행한다.
  5. 남은 5개 항목의 일정을 적는다.

5. 퀴즈

  1. 하드닝이란?
  2. SSH 강화 2가지는?
  3. 설정 전 백업이 필요한 이유는?
  4. 자동업데이트의 위험과 이득은?
  5. 로그를 원격에 두는 이유는?
정답 보기
  1. 불필요를 제거해 공격 표면을 줄이는 것이다.
  2. 키인증과 root 직접 로그인 차단이다.
  3. 실수로 잠그면 복구가 불가하기 때문이다.
  4. 호환성 깨짐 위험 vs 패치 지연 위험이다. 스테이징으로 절충한다.
  5. 침해 시 로컬 로그가 지워져도 추적이 가능하기 때문이다.

5-2. 한눈에 보는 굳히기 순서

sequenceDiagram participant A as 관리자 participant S as 서버 A->>S: 백업 선행 A->>S: 접근 통제 적용 A->>S: 표면 축소 S-->>A: 검증·기록

읽는 법: 백업이 0번입니다. 되돌릴 수 없으면 손댈 수 없습니다.

6. 흔한 실수

  • SSH 설정 후 기존 세션을 끊고 검증하는 경우. 새 세션 확인이 먼저이다.
  • 백업만 하고 복원 시험을 안 하는 경우
